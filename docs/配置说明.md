## 用户数据目录

正式桌面端运行时，KStock 把用户数据写入系统应用数据目录：

- macOS：`~/Library/Application Support/KStock`
- Windows：`%APPDATA%\KStock`
- Linux：`~/.local/share/KStock`

开发模式如果没有设置 `KSTOCK_APP_DATA_DIR`，会 fallback 到仓库内 `.kstock`。发布包不得依赖这个目录。

如果高级用户显式设置 `KSTOCK_APP_DATA_DIR=~/.kstock`，KStock 会尊重该覆盖；但 `~/.kstock` 不是桌面端正式默认路径。

QiLin 的正式运行目录为：

`<KStock 数据目录>/runtime/qilin`

QiLin SQLite 为：

`<KStock 数据目录>/runtime/qilin/data/qilin.db`

## 模型配置

KStock 的模型配置由桌面端「设置 → 引擎 → 模型」管理（增删改 + 设默认），后端写入层在 `scripts/kstock_models.py`，HTTP 路由前缀 `/api/v1/kstock`。配置分三层落盘到用户数据目录：

| 文件 | 作用 | 权限 |
|------|------|------|
| `config/qilin.runtime.yaml` 的 `models:` 段 | 模型清单（name / use / model / api_base / 能力位等），引擎热重载读取 | 0600 |
| `config/secrets.env` | API key 明文，每行 `KEY="value"`；runtime.yaml 只存 `$KEY` 引用 | 0600 |
| `config/prefs.json` | 偏好（如 `default_model`），无敏感数据 | 默认 |

每次写入 `qilin.runtime.yaml` 前，旧文件会备份到 `<数据根>/backups/`，文件名带原 mtime 毫秒时间戳（`qilin.runtime.yaml.<mtime>.bak`）。

### 环境变量引用约定

模型 API key 不直接写进 runtime.yaml，而是以环境变量引用形式存储，避免明文密钥进入引擎配置：

- 明文 `sk-xxxx` → `secrets.env` 的 `KSTOCK_MODEL_<NAME>_KEY="sk-xxxx"`
- runtime.yaml 的 `api_key` 字段 → `$KSTOCK_MODEL_<NAME>_KEY`

命名规则：模型 `name` 转大写、非字母数字转下划线，加前缀 `KSTOCK_MODEL_` 与后缀 `_KEY`。例如 `deepseek-v4` → `KSTOCK_MODEL_DEEPSEEK_V4_KEY`；纯符号 / 空 name 无法生成合法环境变量名时会抛 `ValueError`。

### 引擎热重载与进程环境

引擎（vendor/qilin）基于 mtime 检测 `qilin.runtime.yaml` 变化并自动重载，重载时通过 `AppConfig.resolve_env_variables` 从进程 `os.environ` 解析 `$KEY` 引用。因此 gateway 必须把 secrets 加载到进程环境：

- 启动时 `scripts/run_gateway.py` 的 `_load_secrets_env` 把已有 `secrets.env` 加载到 `os.environ`（启动日志可见 `secrets.env   : 已加载 N 个密钥`）；
- 运行时通过设置页增删模型，`kstock_models` 会同步更新 `os.environ`（`upsert_secret` 写入、`remove_secret` 移除），引擎下次热重载即可解析新引用，无需重启 gateway。

## 对话与流式

工作台对话由前端直连引擎网关（零 BFF 中间层），通过 SSE（Server-Sent Events）流式传输 AI 回复。模型配置完成后即可发消息，无需额外配置。

### 端点

| 方法 | 路径 | 用途 |
|------|------|------|
| POST | `/api/threads` | 创建引擎 thread，返回 `thread_id` |
| POST | `/api/threads/{id}/runs/stream` | 发起流式 run（SSE 响应） |
| GET | `/api/threads/{id}/messages` | 拉取历史消息（懒加载，预留） |

所有写操作带 CSRF double-submit header（`X-CSRF-Token`，值来自登录后下发的 `csrf_token` cookie）。

### SSE 协议

请求体 `stream_mode: ["values", "messages-tuple", "custom"]`。帧格式 `event: <type>\ndata: <json>\n\n`，主要事件：

| event | data 形态 | 前端用途 |
|-------|----------|---------|
| `metadata` | `{run_id, thread_id}` | run 元信息 |
| `values` | `{messages:[...], artifacts, title, ...}` | thread 快照（标题/产物/compaction 检测） |
| `messages` | `[msg_dict, metadata_dict]`（取 `[0]`） | AI 正文流式累加 / reasoning 流 / 工具调用 / 工具结果 |
| `custom` | `{type:"task_started"\|"task_running"\|...}` | 并行 subagent 按 `task_id` 分组 |
| `end` | `null` 或 `{usage}` | turn 完成 |
| `error` / `gap` | 错误信息 | turn 失败 / 断点重连提示 |

`messages` 中 `msg_dict.type` 枚举：

- 非流式快照：`human`（用户，前端已 append 不再处理）、`ai`（AI 回复）、`tool`（工具结果）、`system`（system-reminder，带 `additional_kwargs.hide_from_ui=true` 时前端跳过）
- **流式 chunk**（OpenAI 兼容 provider，如 MiniMax/DeepSeek）：`AIMessageChunk`、`ToolMessage`——含增量 content/reasoning_content/tool_call_chunks；前端 turnReducer 同等处理（按 type 路由到 ai/tool 分支）

ai message 的关键字段：

- `content` — 正文增量（空 content 忽略）
- `additional_kwargs.reasoning_content` / `additional_kwargs.reasoning` — 思考流（DeepSeek / o1 等）
- `tool_calls` — 工具调用请求
- `usage_metadata` — token 用量
- `additional_kwargs.qilin_error_fallback` — 引擎把 provider error 包装成 ai message（前端标记为 error 而非正文）

### RunContext 注入

前端从模型配置构造 `RunCreateRequest.context`：

- `model_name` — 模型 name
- `thinking_enabled` — `supports_thinking` 能力位
- `reasoning_effort` — `supports_reasoning_effort` 时按需传

### Compaction 信号

引擎对长对话会压缩历史上下文（`values` 快照的 `messages` 数量收缩）。前端检测到收缩时给当前 turn 标 `status="compacted"`，UI 显示「上下文已压缩」标注（保留已渲染内容，宁漏勿错）。

### 前端模块

| 模块 | 职责 |
|------|------|
| `lib/sseParser.ts` | ReadableStream → AsyncIterable<SseFrame>（按 `\n\n` 分帧） |
| `lib/turnsClient.ts` | ensureThread / streamRun / fetchThreadMessages + CSRF header |
| `lib/turnReducer.ts` | SSE chunk → assistant turn 状态（纯函数 reducer） |
| `lib/stageInferrer.ts` | pipeline_stage 前端推断兑底（单调推进） |
| `components/ChatFeed.tsx` | turn 聚合骨架 + 自动滚动跟随 |
| `components/AssistantTurn.tsx` | StageBadge + Reasoning + Subagents + Tools + 正文 |
