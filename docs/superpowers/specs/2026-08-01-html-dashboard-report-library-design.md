# HTML 数据看板与报告库设计规格

## 1. 目标与范围

KStock 的研究交付统一为单个自包含 HTML 数据看板。取消报告层面的 Markdown、PDF 和 DOCX 产物；聊天正文与思考过程仍可使用 Markdown 渲染，但不再生成 Markdown 报告文件。

看板采用“研究分区”布局，要求报告中实际纳入分析的每个数据维度都同时提供：

1. 可读的结论、解释或数据质量说明；
2. 至少一种视觉表达（图表、指标卡、时间线、矩阵或结构化表格）。

报告保存到独立的用户数据空间报告目录。历史任务删除只清理线程资源，不级联删除已经归档的报告；报告只能由报告库中的主动删除操作移除。

本规格覆盖：

- 报告输入与渲染契约；
- `analysis-report` 和 `chart-visualization` 技能的职责调整；
- 单文件离线 HTML 的安全约束；
- 报告归档、索引、覆盖和删除生命周期；
- Gateway 与桌面端报告库交互；
- 测试和验收标准。

不包含：PDF/DOCX 导出、Markdown 报告迁移、报告版本历史、外部在线图表服务。

## 2. 设计原则

### 2.1 数据优先

分析结果先组织为结构化数据，再生成看板。渲染器不能从自由文本猜测指标、时间或来源。

### 2.2 适配而非一刀切

图表技能保留各图表类型的字段规范和选型逻辑；不同数据形态使用不同视觉编码。没有适合的图表时使用指标卡、表格、矩阵或时间线，并明确记录选择原因。

### 2.3 缺失可见

无法获取的数据必须显示为 `unavailable` 或 `partial`，同时给出缺失原因、数据范围和补充条件。禁止用空值图表伪装完整分析，也禁止凭空补齐数值。

### 2.4 离线安全

最终 HTML 不加载外部 CSS、JS、字体、图片或接口。来源可以显示为可点击链接，但页面初始化和交互不主动请求网络。

### 2.5 归档独立于任务

报告文件是用户主动保留的研究资产，不属于线程临时输出。线程生命周期和报告生命周期分离。

## 3. 报告数据契约

报告渲染器接收一个 JSON 文档，建议结构如下：

```json
{
  "report_id": "report_01J...",
  "thread_id": "thread_01J...",
  "title": "个股研究看板",
  "subject": {"symbol": "600000", "name": "示例标的"},
  "report_type": "stock-research",
  "generated_at": "2026-08-01T10:00:00+08:00",
  "period": {"start": "2025-01-01", "end": "2026-07-31"},
  "assessment": {"label": "中性", "risk_level": "中"},
  "sections": [
    {
      "id": "fundamentals",
      "title": "基本面",
      "status": "available",
      "summary": "文字结论与证据说明。",
      "metrics": [
        {
          "id": "revenue",
          "label": "营业收入",
          "value": 100,
          "unit": "亿元",
          "change": 0.12,
          "source": "数据源",
          "as_of": "2026-06-30",
          "visual": "line"
        }
      ],
      "charts": [
        {
          "id": "revenue-trend",
          "tool": "generate_line_chart",
          "title": "营业收入趋势",
          "data": [{"time": "2025-Q1", "value": 90}],
          "mapping": {"dimension": "revenue", "role": "trend"}
        }
      ],
      "evidence": [],
      "gaps": []
    }
  ],
  "coverage": [],
  "references": []
}
```

### 3.1 分区状态

每个分区必须包含 `status`：

- `available`：数据足够，完成可视化；
- `partial`：部分数据可用，必须列出缺口；
- `unavailable`：无法分析，必须说明原因和所需数据。

### 3.2 视觉覆盖

每个实际纳入分析的 metric 必须被一个 `visual` 或 chart mapping 引用。渲染前校验器拒绝以下情况：

- 有指标但没有文字说明或视觉映射；
- 图表引用不存在的指标；
- 图表数据缺少来源、时间范围或官方字段；
- 报告包含未声明的分区或字段。

## 4. 研究分区

渲染器按以下顺序展示分区；任务类型可以将不相关分区标记为 `unavailable`，但不应静默移除覆盖信息。

1. **摘要**：核心结论、覆盖范围、关键指标、数据质量。
2. **市场与行业**：指数、板块、相对表现、环境变化。
3. **基本面**：业务结构、财务趋势、资产质量、现金流。
4. **估值**：估值指标、历史区间、同业比较。
5. **技术面**：价格趋势、成交量、结构、关键位和信号。
6. **回测**：配置、收益曲线、回撤、胜率、归因、参数敏感性。
7. **风险与事件**：风险矩阵、事件时间线和触发条件。
8. **来源与数据说明**：来源、抓取时间、分析区间、缺失字段和不可比项。

报告不得输出买入、卖出或持有指令。可以输出研究结论、情景条件、风险等级和需要跟踪的指标。

## 5. 技能职责调整

### 5.1 `analysis-report`

将现有“三份文件交付”改为“单份 HTML 看板交付”：

- 删除 Markdown 文件和深色/浅色双文件要求；
- 删除远程图表 URL 输入；
- 增加报告 JSON 契约、分区状态、metric-to-visual 覆盖校验；
- 负责确定报告类型、分区顺序、文字摘要、证据、风险和数据缺口；
- 调用 `chart-visualization` 生成图表规格；
- 调用唯一 HTML 渲染器输出最终文件；
- 输出自检必须确认只有一个 HTML 文件，且无外部资源依赖。

技能脚本继续承担结构校验和 HTML 渲染，但输出接口改为：

```text
python3 scripts/render_report.py \
  --input report.json \
  --output-dir <temporary-output> \
  --basename <report-id>
```

成功时只生成 `<report-id>.html`。渲染失败时不产生可被归档的部分文件。

### 5.2 `chart-visualization`

保留 26 类图表的选型指南、参考文档和官方字段契约，但调整执行方式：

- `generate.js` 不再调用外部可视化服务；
- 输入经过字段规范化和校验后，输出本地图表 descriptor；
- descriptor 包含图表类型、合法 args、数据维度映射和可用性状态；
- HTML 渲染器使用内嵌运行时绘制 descriptor；
- 同一数据不可被强行套用同一种图表类型。

常见映射包括：时间趋势使用折线/面积，分类比较使用柱状/条形，多维比较使用雷达，组成关系使用饼图/树图，相关性使用散点，流程与关系使用桑基/网络/流程，分布使用直方/箱线/小提琴，结构化明细使用表格。

特殊地图图表只有在离线地理数据随报告内嵌时才生成地图；否则必须输出数据表、文字说明和缺失状态，不得返回远程图片 URL。

## 6. HTML 渲染与预览

### 6.1 单文件内容

HTML 内嵌 CSS、图表运行时代码、报告 JSON 数据和交互逻辑。图表运行时可以由本地 vendored 库和少量 SVG/Canvas 适配器组成，但不能依赖 CDN 或网络请求。

### 6.2 安全策略

报告文件本身使用受限 iframe 预览，建议使用 `sandbox="allow-scripts"`，不授予同源访问。报告内部设置禁止网络连接的 CSP；渲染器对 HTML 文本、属性和来源字段进行转义，禁止注入任意脚本。

### 6.3 交互

- 分区导航与滚动定位；
- 图表 tooltip、图例开关、时间范围切换（数据已内嵌）；
- 指标卡展开证据和来源；
- 缺失数据分区显示原因和补充条件；
- 不提供会改变报告数据的在线操作。

## 7. 报告库与生命周期

### 7.1 文件布局

```text
<data-root>/reports/
  <user_id>/
    YYYY/
      MM/
        DD/
          <report_id>.html
```

报告索引使用现有持久化数据库新增 `report_library` 表，至少包含：

- `id` / `report_id`；
- `user_id`；
- `thread_id`（允许指向已删除线程）；
- `title`、`symbol`、`report_type`；
- `generated_at`、`period_start`、`period_end`；
- `risk_level`、`coverage_status`；
- `relative_path`、`size_bytes`、`sha256`；
- `created_at`、`updated_at`。

### 7.2 生成与覆盖

1. 在临时目录生成并完整校验 HTML；
2. 计算文件摘要并准备目标日期路径；
3. 将新文件原子替换到日期目录；
4. 在同一操作中更新索引；
5. 删除同一 `report_id` 的旧路径；
6. 保证索引失败时不删除旧的有效文件。

同一任务只保留最新版。最新版的 `generated_at` 决定日期分组，重新生成跨日期时移动文件并更新索引。

所有索引读写以 `(user_id, report_id)` 为作用域。不同本地账户不能枚举、读取、覆盖或删除其他账户的报告。

### 7.3 线程删除

线程删除只清理线程自身的 workspace、uploads、outputs、checkpoint 和运行事件等资源。删除逻辑不得扫描或删除 `reports/`，也不得对 `report_library` 执行级联删除。

若报告来源线程已不存在，报告库仍可打开报告；来源信息显示“来源任务已删除”，返回任务操作禁用。

### 7.4 报告库删除

报告库提供独立删除接口。删除时使用确认对话框，并只删除指定的 HTML 文件和索引记录。报告库删除失败时保留索引和文件，向用户显示可重试错误。

## 8. Gateway 与桌面端接口

建议新增：

- `GET /api/v1/kstock/reports`：按日期返回报告摘要列表，支持日期、标的和关键词过滤；
- `GET /api/v1/kstock/reports/{report_id}`：返回元数据和受控文件访问信息；
- `DELETE /api/v1/kstock/reports/{report_id}`：删除报告文件和索引；
- 报告生成完成后由运行链调用归档服务，而不是由前端扫描线程 outputs。

桌面端新增“报告库”侧边栏入口，按日期分组显示报告卡片。打开时在受限 iframe 中预览 HTML；删除使用现有确认对话框模式。设置页的“报告输出”只说明 HTML 看板、离线策略、报告目录和报告技能状态，不再展示 Markdown、PDF 或 DOCX 选项。

## 9. 验收与测试

### 9.1 技能测试

- 合法报告 JSON 能生成单个 HTML；
- 不生成 `.md`、`.pdf`、`.docx`；
- 缺失来源、时间范围、图表映射或非法 chart 字段时拒绝渲染；
- 26 类图表 descriptor 按参考文档校验；
- 外部图片、脚本、样式和网络调用不会出现在 HTML 中。

### 9.2 生命周期测试

- 首次归档创建日期目录、HTML 文件和索引；
- 同任务再次生成只保留最新版；
- 跨日期更新会移动路径而不留下旧版本；
- 删除线程不会删除报告文件或索引；
- 删除报告库条目只删除对应 HTML 和索引；
- 删除失败不会留下孤立索引或丢失旧报告。

### 9.3 前端测试

- 报告库按日期分组和筛选；
- 打开、关闭、删除和来源线程已删除状态；
- iframe 预览无外部资源请求；
- 设置页不再出现 Markdown/PDF/DOCX 选项；
- 现有聊天 Markdown 渲染保持不变。

## 10. 未包含内容

- 报告历史版本与差异比较；
- 云端同步；
- 在线协同编辑；
- 外部图表服务或 CDN fallback；
- PDF、DOCX 和 Markdown 报告导出。
