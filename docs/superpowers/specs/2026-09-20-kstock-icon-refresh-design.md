## 1. 背景与目标

现有应用图标（`apps/desktop/build/icon.icns` / `icon.ico` / `icons/*.png` / `tray.png`）
是二进制孤本：仓库内没有矢量源，也没有任何生成脚本，改一版必须手搓全部尺寸。同时它在
**16–32px 这个最高频的使用尺寸上失效**。本次重构同时解决「可维护性」与「小尺寸可用性」。

目标（按优先级）：

1. 32px 与 16pt 下图形可辨（当前任务栏图标、菜单栏托盘图标均不可辨）。
2. 图标有单一矢量真源，一次改动即可重出全平台全尺寸资产。
3. 建立「应用图标」与「托盘图标」两套各自为尺寸优化的图形，而不是同一张图硬缩。
4. **双品牌**：麒麟（引擎／中文品牌）以篆书朱印呈现；KStock（产品）以品牌绿几何 K 呈现。

非目标：不改动界面内 token 色板、不改动侧栏 / hero 品牌标记（`Marks.tsx`）的现用图形
（色值同步为可选项，见 §6 第 5 项）。

## 2. 现状问题（实测证据）

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | 小尺寸糊 | 32px 下「K」由 4 类形状拼成（青色圆头竖条 / 白斜条 / 白折线 / 琥珀折线） |
| 2 | 色彩与形状过多 | 4 色 + 网格线；16–32px 变噪点 |
| 3 | 尺寸档位自相矛盾 | `icons/128x128@2x.png` 内容占 82%（合规留白）；`icons/32x32.png` alpha 全出血 100% |
| 4 | 托盘无 @2x、运行时缩放 | `menu.ts:217-244` 单张 128px → `resize(22/32)` 后再 `setTemplateImage(true)` |
| 5 | 托盘图形过密 | 折线横穿 K 的干支与两臂，交叉处形成 3 个细碎尖角 |
| 6 | 开发态 Dock 被降级 | `main.ts:119-132` 用 256px PNG 覆盖图标（打包态 AppKit 用含 1024 的 .icns） |
| 7 | 无矢量源 | `grep iconutil/sips/rsvg scripts/ apps/desktop/scripts/ build-release.sh .github/` 无匹配 |

实测补充：`icon.icns` 含 11 档（含 1024/512/256 及 @2x）覆盖完整；`icon.ico` 含 6 档
（16/32/48/64/128/256，**缺 24**）；`icons/` 只有 32/128/128@2x，**缺 Linux 用的 `icon.png`**。

## 3. 选型结论

在 5 个方向（A 一笔 K / B 蜡烛 K / C 实色场 K / D 数据地平线 / E 麒麟印章）中选定，
并按用户决定采用**双品牌**与**篆书**：

| 档位 | 用在哪 | 图形 | 品牌归属 |
| --- | --- | --- | --- |
| **Tier 1** 128–1024px | Dock / 启动台 / 关于页 / 安装器 / 物料 | **双品牌锁版**：朱红白文印（麒麟，篆书）+ 品牌绿 K 印 | 麒麟 + KStock |
| **Tier 2** 16–64px | Windows 任务栏 / 窗口标题 / 通知 / 文件图标 | **C2 深绿实色场 K** | KStock |
| **Tier 3** 菜单栏 16pt | 系统托盘（单色模板图） | **印章外框 + K** | KStock（保留印章形制） |

双品牌使此前的「同一应用两张面孔」不再成立：这是**两个品牌各自的面孔**（朱红 = 麒麟、
品牌绿 = KStock），并带来一条实测的降级规律——尺寸变小时，朱印里的汉字先退为纹理，
而品牌绿 K 印能撑到 32px，视觉重心自然从「麒麟」滑向「K」，与品牌主次一致（见 §4.2）。

### 3.1 为什么必须分档（实测约束，不是设计偷懒）

「麒麟」两字在 16–32px 不可读，由三个实测约束共同决定：

1. **篆书字形尚未落地**：本机无篆书字体；可用来源的覆盖与授权逐项核实结果见 §3.2，
   本设计按「自绘 / 委托自有轮廓」推进，当前出图用 Noto Sans CJK SC Black 占位。
2. **笔画数**：「麟」23 画。16pt 下一个字约 12–16px 见方，平均每画 < 0.7px，物理不可读。
3. **排版**：方框印内 2 字只能竖排（横排会把每字压进 1:2 窄框）。

### 3.2 篆书字形来源（已核实，需用户选一条）

| 来源 | 覆盖 麒/麟 | 授权 | 可得性（实测） |
| --- | --- | --- | --- |
| 霞鹜篆书 LXGW Seal | ❌ | SIL OFL 1.1（可商用可改作） | 可下载，但字表实测不含麒/麟，作者明确不再大扩 |
| 全字库说文解字（CNS11643 篆体） | ✅ | 政府资料开放授权（可商用需署名） | 官方下载页失效、moedict 镜像 404、Wayback 逾时 |
| 方正小篆体 / 汉仪篆书 | ✅ | 字库商业授权（个人免费，商用需购） | 网上副本未授权，**不可用于产品** |
| 崇羲篆体（中研院小学堂） | ✅ | CC BY-ND 3.0：可商用、**禁止改作** | 转轮廓属改作，需先获作者同意 |
| 北师大说文小篆 / 华瑞小篆体 | ✅ | 授权不明 | 风险不可控 |
| **自绘 / 委托自有轮廓** | ✅ | 完全自有 | 需字体设计师；**推荐** |

**推荐自绘 / 委托**：① logo 应拥有字形轮廓而非内嵌字体（字体授权会牵连图标本身的使用范围）；
② 只有自有轮廓才能针对 16–64px 做笔画简化与配重，这正是本项目的核心诉求；
③ 两字成本可控，一次投入永久可用。

## 4. 图形规范（可直接实现）

统一几何基准（macOS 图标网格）：**1024 画布 / 内容区 824（内缩 100）/ 连续曲率圆角**
（超椭圆 `|x/a|^5 + |y/a|^5 = 1` 采样，`a = 412`，中心 512）。全部档位共用该轮廓。

### 4.1 Tier 1 · 双品牌锁版（1024 画布）

底色：squircle 填墨底渐变 `#0d1a16 → #030d0b`（自上而下），内缘描边 `#ffffff` 10%、宽 2.5。

三个版式（`generate_dual.py` 已出稿，**待用户选定一个**）：

- **DB1 · 印下字标**：朱印 620×620 @ (202,128) + 底部 `KSTOCK` 字标
  （Avenir 900 / 90px / 字距 22 / 宣纸白 `#fff8f2`，字心 y=844）。
- **DB2 · 角标 K 印**：朱印 620×620 @ (200,130) + 右下品牌绿 K 小印 178×178 @ (752,742)
  （带 8px 墨色分离环、圆角 30；K 字面 98、描边 24、平口）。
- **DB3 · 对印（推荐）**：朱印 520×520 @ (252,140) + 下方品牌绿 K 印 184×184 @ (420,700)。

**推荐 DB3**：对称、两个品牌都完整、两印共用一套印边语言；且降级表现与 DB2 同级（见 §4.2）。

朱红白文印通用参数（尺寸 S、原点 (x₀,y₀)）：

- 印面：`rect` 尺寸 S、圆角 `0.072S`，填 `#d94436 → #b02f22`（(0.2,0)→(0.8,1)）。
- 印边：内缩 `0.042S`、圆角 `0.058(S-2×内缩)`、描边 `0.026S`、色 `#fff8f2`、不透明度 0.95。
- 印文：竖排「麒」「麟」，`Noto Sans CJK SC / 900`（**待替换为自有篆书轮廓**），
  字号 `0.35S`，字心为印心 y ∓ `0.19S`，色 `#fff8f2`。
  - DB3 实参：S=520、内缩 22、描边 14、字号 188、半间距 98。

品牌绿 K 印：填 `#1e9a79 → #178267`（(0.15,0)→(0.85,1)），白内框（DB3：内缩 11、描边 6、不透明度 0.9），
K 为白色平口几何字（DB3：字面 96、描边 24）。

### 4.2 尺寸降级规则（实测得出，必须实现）

| 尺寸 | 呈现 | 依据 |
| --- | --- | --- |
| ≥256px | 完整双品牌锁版（麒麟可读 + K 印可读） | 实测 256px 两印均可读 |
| 128–64px | 同一张图直接缩放：麒麟退为纹理，**绿色 K 印仍可辨** | 实测 128/64px |
| 32px | Tier 2 图形（C2），不再缩 Tier 1 | 实测 Tier 1 在 32px 整体糊 |
| 16pt 托盘 | Tier 3（印章框 + K） | 汉字在此尺寸无解 |

即：**不需要人工挑选尺寸档**——Tier 1 自身在 128/64 的降级是可接受的；
只有 32px 及以下切到 Tier 2/3。

### 4.3 Tier 2 · C2 深绿实色场 K（1024 画布）

- 场色：squircle 填线性渐变 `#1e9a79 → #14775e(55%) → #0c5a45`，方向 (0.12,0)→(0.88,1)。
- 受光：径向渐变 `#ffffff` 不透明度 0.05 → 0.015(55%) → 0，圆心 (0.28,0.16)、半径 0.92×内容区。
- 字形：白色几何 K、**平口**、描边 96：`M368 272 V752`、`M368 512 L652 272`、`M368 512 L652 752`。
- 内缘高光：同 §4.1。
- 对比度实测：白字 vs 场色 **2.96:1（最亮处）～ 8.08:1（最暗处）**，全图 ≈3:1。

### 4.4 Tier 3 · 托盘模板图（32 画布 = 16pt@2x，纯黑 + alpha）

- 印边框：`M6.4 3 H25.6 A3.4 3.4 0 0 1 29 6.4 V25.6 A3.4 3.4 0 0 1 25.6 29 H6.4
  A3.4 3.4 0 0 1 3 25.6 V6.4 A3.4 3.4 0 0 1 6.4 3 Z`，描边 2.4，无填充。
- K：描边 3、圆头：`M11.4 8.6 V23.4`、`M11.4 16 L21 8.6`、`M11.4 16 L21 23.4`。
- 安全区：图形范围 3..29（四周 3px = 1.5pt）。
- 模板图铁律：**仅纯黑 #000000 + alpha**，不得有灰度或彩色；不含渐变、投影、<1.5pt 的线与 <2pt 的点。

## 8. 验收标准

1. `bash scripts/build-icons.sh` 可在干净环境一次性重出全部资产，重复执行结果幂等（字节级稳定）。
2. 资产齐全：`icon.icns`（11 档含 1024）、`icon.ico`（7 档含 24）、`icons/` 16→1024 + `icon.png`、
   `trayTemplate.png` + `trayTemplate@2x.png`、Windows 彩色托盘图。
3. **留白一致**：`icons/` 全部 PNG 的 alpha bbox 内容占比 80%±2%（当前 `32x32.png` 为 100%，必须修正）。
4. **托盘质量**：`trayTemplate.png` 仅含纯黑与透明（无灰度）；32 素材下 K 描边 ≥3px；
   浅色（#ececec）与深色（#1c1c1e）菜单栏上与系统图标并排目视等重。
5. **小尺寸可辨**：32px 下 Tier 2 的 K、Tier 3 的「框 + K」均可辨（与现有图标同尺寸对比截图）。
6. **降级规则成立**（§4.2）：256px 双品牌两印可读；128/64px 绿色 K 印仍可辨；32px 切 Tier 2。
7. **对比度**：Tier 2 白字 vs 场色全图 ≥ 2.9:1。
8. **视觉验收**：Dock、macOS 菜单栏（浅/深）、Windows 任务栏与托盘、Windows 安装器图标、
   Linux 应用列表，逐项提供真实截图；不通过则返工。
9. `bash scripts/check-ci.sh` 通过。
