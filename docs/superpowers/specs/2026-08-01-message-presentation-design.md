# 对话消息展示优化设计

## 背景

当前助手回复会将工具调用逐组渲染为多条边框卡片。工具数量较多时，这些卡片占据主要视觉空间，结果摘要、状态和正文的权重相近，导致长篇研究结论难以连续阅读。助手消息前的图标也不符合预期。

本次仅优化桌面端对话工作台的助手消息展示，不改变引擎事件、会话存储或工具调用数据结构。

## 目标

- 将正文提升为助手消息的主视觉内容，改善长文本的阅读节奏。
- 将本轮工具调用收敛为一条可扫描、可展开的活动摘要。
- 移除助手消息前的头像图标及其空白占位。
- 保留所有工具调用参数和结果的按需查看能力。
- 在流式过程中保持摘要高度稳定，减少页面跳动。

## 非目标

- 不调整后端 SSE 协议、`ChatMessage` 或 `ToolCall` 的数据结构。
- 不重新设计整个应用主题、侧栏或输入区。
- 不增加浏览器端视觉验收；由用户自行完成最终界面确认。

## 交互与视觉设计

### 助手消息

助手正文与消息列左边缘对齐，不再显示头像或保留头像宽度。阶段标识保留为低调的顶部状态信息，用于区分执行状态而非作为装饰性主体。

正文使用清晰的段落、标题、列表、代码块和行内代码层级。工具活动与正文之间保持固定间距，使执行过程属于辅助信息，阅读结论时不会被多行工具卡片打断。

### 工具活动摘要

当开启“显示工具调用”偏好且本轮存在工具调用时，助手消息只显示一条摘要行：

`状态图标 + 已完成/执行中/有失败 + N 次工具调用 + M 类工具 + 最新结果摘要 + 展开箭头`

在窄窗口中，先隐藏“工具类别数”和“最新结果摘要”，始终保留状态、调用次数和展开按钮。摘要内容须省略而非换行，以保持稳定高度。

展开摘要后，按工具名称分组显示调用次数及每组的最近结果摘要。用户可继续展开单次调用，查看原有的参数和完整结果。关闭“显示工具调用”时，摘要与详情均不渲染。

### 状态

- 执行中：蓝色进度图标与“执行中”标签。
- 已完成：低饱和绿色图标与“已完成”标签。
- 有失败：克制的红色图标与“有失败”标签。
- 无工具调用：不显示工具活动摘要。

状态更新只能修改摘要内容，不能引入额外行高或造成消息列重排。

## 实现边界

`AssistantTurn` 负责移除头像并在当前工具调用区域渲染新的聚合摘要组件。新组件从现有 `ToolCall[]` 计算调用总数、工具类别数、汇总状态和最后一条有内容的结果摘要。现有 `ToolCallGroup` 与 `ToolCard` 继续承担展开后的分组和单次详情展示。

样式集中在 `styles.css`，沿用现有深色金融工作台色彩。摘要使用紧凑、弱边框的容器，避免每个工具调用都形成高对比的大卡片。

## 验证

- 为汇总统计与状态判定补充单元测试。
- 验证无调用、执行中、已完成、失败、混合状态及隐藏工具调用开关。
- 运行桌面端 Vitest 测试和生产构建。
- 不启动前端浏览器验收；最终视觉确认由用户完成。
