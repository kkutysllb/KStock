# KStock 发布契约

发布链四层（本地入口 → CI → 打包契约 → 客户端消费）共同遵守的**单一事实源**。
任何一处改动必须同步「必须同步的消费方」列的全部行——G3 缺口（发布执行体与
打包契约各说各话）就是本表缺位的直接后果。任务编号与红路径清单见
[发布改造计划](../../plans/2026-09-28-release-pipeline-refit.md)。

**落地状态**：✅ 已落地 / ⏳ 待落地（括号内为计划任务号）。

## 3. secrets 清单与注入范围

| Secret | 用途 | 注入范围 |
|---|---|---|
| `APPLE_SIGNING_IDENTITY` | 闭包 Mach-O 预签 + `.app` 签名身份 | **仅 macOS** |
| `MAC_CERTIFICATE`（`CSC_LINK`） | `.app` 外壳签名（.p12 base64） | **仅 macOS** |
| `MAC_CERTIFICATE_PWD`（`CSC_KEY_PASSWORD`） | .p12 口令 | **仅 macOS** |
| `APPLE_ID` + `APPLE_APP_SPECIFIC_PASSWORD` + `APPLE_TEAM_ID` | notarytool 公证 | **仅 macOS** |

规则：

1. **平台化注入**：非 macOS 步骤不得出现任何 `CSC_*` / `APPLE_*` 环境变量。
   历史事故（KCoder 同踩）：全局注入 → Windows Setup exe 被 Apple 证书签名
   （Authenticode NotValid）→ electron-updater 拒更新，且 `app-update.yml` 被
   写入 mac 证书 CN 作 `publisherName`（双重失败，V7 钉死）。
2. **fail-closed 公证（双防线，红路径实测修订）**：electron-builder 26 的
   `mac.notarize: true` 在生成不了选项时会**跳过公证并继续出包**（实测
   `skipped macOS notarization` + exit 0），不构成门禁——
   **前置门** = `check-release.sh` / `build-desktop.sh` 的凭据齐备检查（macOS
   发布配置缺任一凭据即失败）；**事后门** = 产物层 V5（`stapler validate`、拒
   adhoc）。杜绝「凭据失效 → 静默出未公证包 → 用户被 Gatekeeper 拦」。
3. **fail-closed 的位置**：发布门（`check-release.sh` 入口在 macOS 要求身份齐备，
   R1.6）；`build-runtime-bundle.sh` 本体保持本地可用（缺身份 = 跳过预签；
   非 Darwin = 不碰预签脚本）。
4. **显式未签名通道**：仅 `KSTOCK_UNSIGNED_BUILD=1`（R3.3）。CI 上凭据缺失应
   **失败**，不得悄悄降级成未签名产物。

## 4. 不可变 tag 与发布事故处置 SOP

**事实**：`push: tags` 事件的 workflow 取自**被推 tag 的 commit**——tag 一旦推送，
其构建/发布流程即冻结；改 main 对已推 tag 无效。workflow 结构性改动一律先走
`vX.Y.Z-rc.N` 演练（R6.1 八项清单全过）再发正式版。

```
1. 判断缺陷来源：
   a) 仓内脚本/配置缺陷（可在 main 修）→ 修完 delete-tag 重发；
   b) workflow 自身缺陷 → 必须先修 main，再 --delete-tag 重打 tag
      （新 tag 指向含修复的 commit）。
2. 处置命令：
   ./build-release.sh --delete-tag vX.Y.Z          # 删本地 + 远程 tag（脚本已支持）
   git checkout main && git pull && <修复并提交>
   ./build-release.sh vX.Y.Z --yes
3. 已发布版本的正文补写（无需重发）：
   bash scripts/publish_release_notes.sh vX.Y.Z /tmp/n.md
   gh release edit vX.Y.Z --notes-file /tmp/n.md
4. 撤回坏包：gh release delete-asset <tag> <name>，并同步处理 latest*.yml 对应条目
   （或直接重发更高 patch 版本，靠 verify_release_assets 的 yml↔资源名交叉比对兜住）。
5. 回滚：electron-updater 不自动降级 → 只能发布更高版本号回滚。
```

## 6. 发布流程速查

```
本地：./build-release.sh vX.Y.Z     # 前置：release/vX.Y.Z.md 必须存在（R1.3）
      bump → 门禁 → commit → annotated tag → atomic push → watch → 资产校验
CI：  push tag 或 workflow_dispatch(tag)   # 平台失败可单平台补跑（R2.3）
      引擎引导 → 闭包构建 → 打包（mac 签名+公证）→ 产物层门禁 → publish
客户端：electron-updater 静默下载 + 退出时安装（失败可见、可重试）
```
