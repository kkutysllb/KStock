## 三、发现并修复的问题

### 3.1 平台配置：技能白名单机制（已修复）

**现象**：subagent 报 `Tool 'bash' is not allowed by the active skill policy`，仅剩 4 个内置工具。

**根因**：`qilin.runtime.yaml` 的 `agents.general-purpose.skills` 是**显式白名单语义（非追加）**，原只有 13 个旧技能；新同步的 18 个技能不在白名单 → 技能激活后 fail closed。

**修复**：白名单扩展为 31 技能（`qilin.runtime.yaml` + `config/qilin.config.yaml` 模板），重启 gateway 生效。

### 3.2 密钥声明：a-stock-screener 缺 IWENCAI_API_KEY（已修复）

**现象**：CLI 报 `问财查询失败: API 密钥未设置`（data_adapter.py 问财优先）。

**修复**：SKILL.md `required-secrets` 补 `IWENCAI_API_KEY`（vendor + KSkills 双份）。

### 3.3 代码 bug：futures-analysis 数据全空 + 崩溃（已修复，4 处）

| # | 位置 | 问题 | 修复 |
|---|------|------|------|

## 四、关键机制发现（对后续编排有直接影响）

### 4.1 密钥注入依赖技能激活

- subagent **必须通过 read_file 读 SKILL.md** 才会触发技能激活（skill_context 登记）
- 技能激活后，SkillActivationMiddleware 才会向 bash 调用注入 `required-secrets` 声明的密钥（TUSHARE_TOKEN / IWENCAI_API_KEY）
- **测试/编排任务模板必须保留"第一步读 SKILL.md"**，否则技能未激活 → 密钥未注入 → 数据全空（futures-analysis 曾因此数据为 0）

### 4.2 沙箱路径替换

- 沙箱内 `/mnt/user-data/workspace/` 等路径会被翻译为宿主机绝对路径（`~/Library/Application Support/KStock/runtime/...`）
- shell 重定向（`>`、`| tee`）到被替换路径会失败（`zsh: is a directory`）
- **编排任务应避免要求子代理重定向输出到文件**，直接取 stdout

### 4.3 长 SKILL.md 会耗尽 turn 预算

- dcf 的 SKILL.md 1311 行曾导致子代理 max_turns=150 烧满
- **任务模板应限定"读前 N 行 / 搜索相关段落"**，不要求全文阅读
