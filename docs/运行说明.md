# 运行说明

KStock 桌面端由两部分组成：

- **QiLin gateway**（Python / FastAPI）：内置在 `vendor/qilin`，由 `scripts/run_gateway.py` 以 uv 管理的虚拟环境启动，提供认证、线程、运行等 HTTP API。
- **桌面前端**（React + Tauri）：`apps/desktop`，通过 HTTP + Cookie 对接 gateway。

## 1. 环境准备

需要 Node.js、pnpm 与 [uv](https://docs.astral.sh/uv/)。

```bash
# 前端依赖
pnpm install

# Python 运行时：在项目根目录创建 .venv 并以 editable 方式安装 vendor/qilin
uv venv
uv sync
```

`uv sync` 会按根目录 `pyproject.toml` 安装 qilin 及 gateway 运行所需的 fastapi / uvicorn / bcrypt / email-validator 等。

## 2. 启动 gateway

```bash
uv run python scripts/run_gateway.py
```

默认监听 `http://localhost:18001`。启动时会：

1. 解析跨平台用户数据根目录（见下「用户数据空间」）并建立目录结构；
2. 生成运行时配置 `qilin.runtime.yaml`，显式写入 SQLite 绝对路径；
3. 把已有 `config/secrets.env`（模型 API key）加载到进程环境，供引擎热重载时解析 `$KEY` 引用；
4. 注入桌面端 webview 的 CORS origin 白名单；
5. 打印数据根目录、运行时配置、QILIN_HOME、SQLite 路径、CORS origins、已加载密钥数；
6. **接入内置 python client**：若存在构建产物 `dist/kstock-gateway/_internal/python-runtime/`（由
   `scripts/build-gateway-bundle.sh` 生成，与打包版同源同一套），会把它前置到 PATH 并导出
   `KSTOCK_PYTHON`，agent 技能脚本的 `python3` 直接解析到内置解释器（依赖/凭证开箱即得）——
   开发模式与打包模式共用同一套内置 client，验证效果一致。产物缺失时打印 warning 并回退
   系统 python3，此时需先执行 `scripts/build-gateway-bundle.sh` 构建。

> 开发模式不导出 `PYTHONHOME`（避免干扰 gateway 自身标准库定位）；打包态（frozen）才设置。

可用环境变量覆盖：

| 变量 | 默认 | 说明 |
|------|------|------|
| `GATEWAY_HOST` | `localhost` | 绑定地址；保持 `localhost` 以满足前端 same-site cookie |
| `GATEWAY_PORT` | `18001` | 监听端口 |
| `GATEWAY_CORS_ORIGINS` | 内置桌面端 origin | 逗号分隔的额外允许 origin |
| `KSTOCK_APP_DATA_DIR` | 系统 app data 目录 | 覆盖用户数据根目录（多实例 / 调试用） |

## 3. 启动桌面端

```bash
# 网页层调试（Vite dev server，http://localhost:1420）
pnpm -C apps/desktop dev

# Tauri 原生桌面窗口（会自动拉起 Vite dev server）
pnpm -C apps/desktop tauri:dev
```

> 开发态前端默认连接 `http://localhost:18001`，可经 `apps/desktop/.env` 的 `VITE_GATEWAY_URL` 覆盖。

## 4. 用户数据空间

正式运行时用户数据落在用户主目录 `~/.kstock`（macOS / Windows / Linux 统一，详见 `docs/用户数据空间组织设计.md`）：

- 默认根：`~/.kstock`（可用 `KSTOCK_APP_DATA_DIR` 环境变量覆盖）
- 历史版本（v1）位于系统应用数据目录（如 macOS `~/Library/Application Support/KStock`），首次启动自动迁移到 `~/.kstock`

结构：

```text
KStock/
  config/qilin.runtime.yaml      # 运行时配置（由 scripts/run_gateway.py 生成）
  runtime/qilin/
    data/qilin.db                # QiLin 主库（用户、线程、运行、会话）
    .jwt_secret                  # 认证 JWT 密钥
  product/  logs/  ...
```

> 仓库内不再保存任何用户数据；`.gitignore` 已防御性忽略 `.kstock/` 与 `.qilin/`。

## 5. 认证

gateway 自带完整本地账户体系（HttpOnly Cookie + JWT + CSRF）：

- 首次启动后，前端落地页点「注册」创建本地账户（邮箱 + 至少 8 位密码）；
- 注册成功后 gateway 同步下发会话 cookie，自动进入工作台；
- 下次启动时前端会探测 `/api/v1/auth/me`，已登录则直接进入工作台；
- 工作台侧边栏底部显示当前账户邮箱，可「退出登录」。

## 6. 模型配置

工作台对话需要至少一个可用模型。模型配置通过设置页管理，无需手动编辑文件：

1. 工作台侧边栏底部点「打开设置」→ 左侧「引擎 → 模型」；
2. 点「+ 添加模型」，从 provider 模板（DeepSeek / OpenAI 兼容 / Claude / vLLM 等）快速创建，或「空白自定义」；
3. 填写 `model`、`api_base`、`api_key`（明文，仅写入 `secrets.env`，不进 runtime.yaml）等字段，保存；
4. 在模型列表点「设为默认」，该模型会成为新会话的默认选择；
5. 返回工作台，消息输入框左侧的模型选择器会列出已配置模型并选中默认项；未配置任何模型时发送按钮禁用并提示「未配置模型（请到设置页添加）」。

模型配置的存储格式、环境变量引用约定与备份机制见 `docs/配置说明.md` 的「模型配置」一节。

## 7. 运行测试

```bash
# Python（gateway 侧）
uv run pytest tests -q

# KStock 模型配置写入层（runtime.yaml / secrets.env / CRUD 端点）
uv run pytest tests/test_kstock_models.py -q

# 前端单元测试（含流式模块：sseParser / turnsClient / turnReducer / stageInferrer / sessionStore / App 集成）
pnpm -C apps/desktop test

# Playwright 端到端
pnpm -C apps/desktop exec playwright test
```

- `apps/desktop/dist/`：前端构建产物

## 9. 打包版行为（安装包 / 自动更新）

通过 `build-release.sh` 或 GitHub Actions 产出的安装包与开发模式有两点差异：

1. **内置 gateway**：安装包资源目录（`Resources/gateway/`）内嵌 PyInstaller 打包的
   自包含 gateway（Python 运行时 + 全部依赖 + 技能包 + 配置模板）。应用启动时自动拉起，
   退出时联动终止，用户无需安装 Python / uv；开发仓库的 `dist/kstock-gateway` 不参与运行。
2. **自动更新**：侧边栏用户位置右侧有隐藏下载图标，检测到 GitHub Release 有新版本时
   出现（红色角标），点击下载后自动重启安装。机制与发布流程详见 `docs/发布说明.md` 的
   「自动更新」章节。
