2 · 四个视觉方向

四个方向刻意在视觉语言上分开（不是同一图形的配色变体），这样才有得比： 字母体 vs 市场语义 vs 实色场 vs 去字母化。每张图都按 macOS 图标网格绘制 （1024 画布 / 824 内容区 / 连续曲率圆角），下面同时给出 32px 真实像素与托盘双底色效果。 方向 C 有两种调性（品牌亮绿 C1 / 深绿保对比 C2），合计 5 张候选图。

方向 C

实色场 K

Color Field · 品牌绿整块场 + 白色 K，最接近 macOS 原生观感

3 · 追加方向 E：麒麟印章（你指定的方向）

要求：用「麒麟」两个汉字做成印章。这个方向在大尺寸上最有力（辨识度、文化语义、与 --dsw-specific-brand-seal-fill「品牌印记」的既有词汇完全一致），但在小尺寸上撞到两个字面意义上的物理下限。 下面把所有约束实测出来，再给出可落地的分档方案。

阅读提示（本节有先后两稿）：下面「三个执行」与「32px 实测」是黑体字形占位稿， 用于先定版式；再往下的「双品牌结构」与「篆书出稿」是拿到篆书字形后的最新稿， 字形、排法、版式都以最新稿为准（并且推翻了本节一处判断，见「约束 3」）。

约束 1 · 字体

fc-list 实测本机可用中文字体只有 Noto Sans CJK SC（含 Black）、Songti SC、Heiti SC、Hiragino 系列—— 没有篆书/隶书。

所以本稿是「现代粗黑体印」。真正的篆书印章需要字体授权或手工描形。

附注：篆书（尤其缪篆）笔画等宽、布白均匀，小尺寸表现明显优于黑体—— 字体不只是风格问题，也直接决定 16–32px 能不能看。

约束 2 · 笔画数下限

「麟」23 画。16pt 托盘里一个字只有约 12–16px 见方，平均每画不足 0.7px—— 两个汉字在 16pt 托盘里不可能读出来。

这不是设计取舍，是物理下限。证据见下方托盘实测最后一格（单字「麟」直接进 16pt）。

约束 3 · 排版（已实测修正）

我先前判断「2 字方印只能竖排」，拿到篆书字形后实测推翻了这个判断： 小篆字形本身瘦长，实测墨迹宽高比 0.644（麒）/ 0.675（麟）， 所以方印里横排才填得满（右麒左麟，篆印自右向左读）；竖排反而两侧留白一大片。

「横排会压扁字形」只对楷书／黑体这类方正字形成立，对篆书不成立——见下方篆书实测。

为什么托盘必须是另一个图形

  • 托盘是单色模板图：朱红/品牌绿在这里全部消失，只剩轮廓。
  • 汉字在 16pt 无解（约束 2），所以托盘换用拉丁 K： 3 笔、等宽、任意尺寸可读，且与 Marks.tsx 的 K 字标同源。
  • 外框保留「印」的形制——这是托盘上唯一还能承载品牌的部分。
  • 若你不接受托盘出现英文字母，唯一可读的替代是放弃字形， 只留印章轮廓（会与「KStock 是个什么应用」脱钩），或退回方向 A/C 的 K 模板图。
一个品牌层面的问题，需要你确认：麒麟 在本项目里是引擎的名字 （README：「构建在 QiLin 3.x 引擎『一切皆插件』平台之上」，代码目录 vendor/qilin）， 而产品名是 KStock。把「麒麟」放到应用图标与托盘上，等于让应用图标承载引擎品牌。 两种都是成立的选择，但含义不同：
· (a) 有意为之——把中文品牌统一为「麒麟」，KStock 只作英文名/发行名（图标 = 麒麟印章，最干净）；
· (b) 双品牌——KStock 是产品、麒麟是引擎，图标上同时出现（印章 + 小字 KSTOCK 或角标 K，代价是 1024 以下小字先糊）。
本稿按 (a) 出图。选 (b) 我再补一版合印稿。

双品牌结构（按你的决定：麒麟 = 引擎／中文品牌，KStock = 产品）

走双品牌之后，前面「一张图两张面孔」的问题反而消失了：这不是同一品牌的两张脸，而是两个品牌各自的脸。 而且双色分工天然成立——朱红 = 麒麟（传统、引擎、篆印），品牌绿 = KStock（产品、现代、几何 K）。 三个 Tier 1 版式如下（篆书字形位置当前用黑体占位，见下一节）。

DB1 · 印下字标 ← 已选定

朱印居中偏上 + 底部 KSTOCK 字标（宽字距）。 最像标准品牌锁定（lockup），适合关于页 / 官网 / 物料。

已按你的意见去掉右下角的绿 K 印；字标颜色有白 / 品牌绿两版，见下。

DB2 · 角标 K 印

朱印（麒麟）为主，右下角压一枚品牌绿 K 小印（带墨色分离环，像骑缝 / 落款）。 产品标识与引擎标识同时在场，且不占版面。

风险：两印相接，1024 下有分离环啃掉朱印白印边的观感问题，需再微调 2–3px。

DB3 · 对印

上朱印（麒麟）+ 下绿印（K）居中对齐，像「对章」。 版式对称、层级清楚，绿印带白内框，与朱印共用同一套印边语言。

风险：主印被压到 520px，麒麟两字相应变小。

现状：出稿用的是 Wikimedia Commons 的小篆字形（已下载到 glyphs/，来源与授权状态见 glyphs/README.md）， 两字结构已人工核对无误；但文件页的具体协议与署名要求尚未取到（本机到 Commons 的连接时通时断）， 落地前必须打开那两个文件页确认。若协议为 ND 或 SA，则不能改造成产品轮廓。

生产建议：仍走自绘／委托，把「麒麟」两字做成自有轮廓（SVG path）。
理由有三：① 图标是 logo，logo 应该拥有字形轮廓而不是内嵌字体（字体授权会牵连到图标本身的使用范围）； ② 只有自有轮廓才能针对 16–64px 做笔画简化与配重——这恰恰是本项目要解决的核心问题，字体文件给不了这个自由度； ③ 两个字成本可控，一次投入永久可用、无授权风险。

在你定这条路之前，本页所有「麒麟」字样都是 Noto Sans CJK SC Black 占位： 版式、印框比例、色彩、降级规则都已定稿，换字形不需要重排版面。

4 · 托盘图标专项规范

托盘是这次重构里最容易翻车的一半（方向 E 的「印章框 + K」同样受本节全部规则约束）：它不能是应用图标的缩小版。下面是本次四个方向共同遵守的规则， 也是落地时要写进生成脚本的硬约束。

规则

  • 纯黑 + alpha：macOS 模板图只允许纯黑不透明像素，出现灰度/彩色会被系统反色成脏灰。
  • 光学配重 +40%：同一字形在 16pt 下需比 1024 图标加粗约 40% （本例：10.2% → 14.2% 字重占比），否则细得像没描边。
  • 笔画数 ≤3、无细节：小于 1.5pt 的线、小于 2pt 的点一律删除 （所以 A 去掉数据点、B 去掉影线、D 去掉网格与光晕）。
  • 供 1x + 2x 两张：trayTemplate.png(16) + trayTemplate@2x.png(32)， 交给 Electron 合成，不再运行时 resize()。
  • 安全区：字形四周留 ≥1pt（32 画布里 ≥2px），避免贴边被菜单栏裁切。
  • 视觉重量对齐系统图标：把图标贴进真实菜单栏与 Wi-Fi/电池并排比对，而不是只看放大图。

四方向托盘 16pt 实测（浅 / 深菜单栏）

每格：16pt 真实 / 22pt 真实 / 16pt 2× 放大。 深色行已按系统模板反色规则还原。

结论：A 与 C 在 16pt 下字形最稳；B 的蜡烛干支在 16pt 会糊（需简化版）； D 可读但无字形记忆。

推荐：C 作主方案 + A 作为「保守版」备选。
理由：重构要解决的首要问题是 32px 与 16pt 的清晰度（诊断第 1、4、5 条），C 在这两个尺寸上都是四者最佳， 且与 macOS 原生图标的记法一致（大色块 + 简单字形）；A 则是风险最低的「只治清晰度、不动品牌感」路线， 适合不希望 Dock 观感变化的场景。B 建议只在「行业辨识度优先」且接受能力退化时选用； D 更适合网站/物料等大尺寸场景，不建议作为应用与托盘图标。

若选 C，还要定一件事：C1 品牌亮绿（忠于现有 token，Dock 最跳，浅端字形对比 1.93:1） 还是 C2 深绿保对比（全图≈3:1，字形最实，色调更沉稳）。我倾向 C2： 图标要在 16px 任务栏与 32px 窗口标题里工作，字形的实感优先于色相亮度；品牌亮绿仍保留在界面 token 里。

方向 E（麒麟印章）的定位

维度E 的实测结果

128px 以上可读性「麒麟」两字完整可读（见 256px 三执行图）

结论：E 与 C 不是二选一，而是分工。
推荐组合 「E1 或 E2 作 Tier 1 大尺寸印章 + C2 深绿实色场 K 作 Tier 2 / Tier 3 小尺寸与托盘」： Dock 里是朱印（文化身份），任务栏与菜单栏里是绿底白 K（清晰度优先）。 代价是同一应用在系统里有两张面孔——这是印章类图标（受汉字笔画数约束）的必然结果， 成败取决于两张面孔共用一个字标（麒麟 / K）与同一套圆角方轮廓，视觉上仍属同一家族。

如果你要的是「一枚图打通所有尺寸」，那 E 不成立，应选 C2：它的 32px 与 16pt 都是四者最佳。
