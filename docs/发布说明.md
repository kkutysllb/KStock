# 发布说明

## 一键发布

在项目根目录执行：

```bash
./build-release.sh v0.1.0
```

脚本会自动完成：

1. 校验版本号格式（`vX.Y.Z`）、git 工作区状态、当前分支与远端同步情况；
2. 同步版本号到 `package.json` / `apps/desktop/package.json`（2.0 起无 Python 工程）；
3. **硬门**：`release/<tag>.md` 发布说明与 `docs/项目审计-<版本>.md` 审计报告必须已存在（见下节）；
4. 本地预检 `scripts/prepush.sh`（审计三门两报告 + 引擎契约 13 项 + 打包资源契约 + `check-ci.sh` 全量测试与类型检查；本机桌面构建不在此链——需要时手动跑 `scripts/check-release.sh`）；
5. 生成发布说明（自上一 tag 以来的提交）；
6. 提交版本号、打 annotated tag、推送 `main` 与 tag；
7. 推送 tag 触发 GitHub Actions `Release` 工作流，构建完成后安装包自动上传到 GitHub Release。

常用参数：

| 参数 | 说明 |
|------|------|
| `--skip-check` | 跳过本地预检（构建交给 CI；审计报告硬门仍在） |
| `--no-push` | 只提交 + 打 tag，不推送 |
| `--force` | 工作区有未提交改动 / 本地落后远端时仍继续 |
| `--watch` | 监控最近一次 Release workflow 运行结果（需已安装 GitHub CLI） |

## 发版要求（门禁）

对齐 KCoder 的发版口径，本仓的发版门禁分五层，前两层是**硬门**（缺失直接拒绝发版）：

| 层 | 门 | 位置 | 失败行为 |
|----|----|------|----------|
| 1 | 发布说明 `release/<tag>.md` | `build-release.sh` | 缺失拒绝（`--allow-missing-notes` 应急） |
| 2 | 审计报告 `docs/项目审计-<版本>.md` | `build-release.sh` `require_audit_report` | 缺失拒绝（无跳过开关） |
| 3 | 审计 + 引擎契约 + 打包资源契约 + CI 全量车道 | `scripts/prepush.sh`（`--skip-check` 可跳过） | 非零退出即中止 |
| 4 | tag 冲突 / 远程 tag / 落后远端 | `build-release.sh` | 中止 |
| 5 | 打包链：签名公证 fail-closed + 产物门禁 V1–V8 + 发布后资产交叉比对 | CI `release.yml` → `check-release.sh` → `verify-desktop-artifacts.sh`；本地 `--watch` | 构建失败 / 资产不符即红 |

审计门 `node scripts/audit.mjs` 的分节（与 KCoder `scripts/audit.mjs` 同构）：

- **[门] TYPECHECK**：复用 `check-ci.sh --types-only`（同一套 tsc 命令单一事实源）；
- **[门] LINT**：oxlint 扫 `kstock` / `apps/desktop` / `scripts`，0 error 才过，warning 逐条列出；
- **[门] SECURITY**：`pnpm audit --prod --audit-level high`，root 与 `kstock` 两个工作区根各一次；
- **[报告] DEAD EXPORTS**：ts-prune 候选 + 全仓引用交叉核对（过滤单 project 视角的跨包消费假阳性）；
- **[报告] UNUSED DEPS**：depcheck 逐包「声明未用 / 用了未声明」。

报告项不阻断命令退出，但必须逐条处置（修复或在审计报告中写明豁免理由）后才能发版。
原始输出落盘 `.release-logs/audit-<时间戳>.log` 便于取证。

## 发布产物

| 平台 | 产物 | 签名 |
|------|------|------|
| macOS (Apple Silicon) | `.dmg` / `-mac.zip`（updater） | Developer ID 签名 + notarytool 公证（staple） |
| Windows (x64) | `.exe`（NSIS） | （代码签名证书后续补充） |
| Linux (x64) | `.deb` | （无额外签名） |

> 发布仅覆盖上述三个平台，不提供 macOS Intel 产物；Linux 不打 AppImage
> （linuxdeploy 在 GitHub Actions 上不稳定，v0.1.1 已确认 deb 可用）。

## 自动更新（electron-updater）

桌面端内置自动更新，真正开箱即用：

- 侧边栏用户位置右侧的**隐藏下载图标**：默认不显示，检测到新版本时出现（带红色角标），
  悬停提示版本号；点击后下载更新（下载中图标旋转并提示已下载体积），
  下载完成后自动重启并安装；失败可点击重试。
- 更新源：GitHub Release 的 `latest-mac.yml` / `latest.yml` / `latest-linux.yml`
  （electron-builder 构建时自动生成，各平台独立一份），`electron-updater` 读取后下载差分包。
- 产物形态：macOS `.zip` / Windows `.exe`（NSIS）/ Linux `.deb`（含 blockmap 增量更新）。

## 签名与安全配置

macOS 签名与公证使用仓库 Secrets（已在 GitHub 仓库配置完成）：

| Secret | 用途 |
|--------|------|
| `MAC_CERTIFICATE` | Apple Developer ID 证书（base64 编码的 p12，electron-builder `CSC_LINK` 读取） |
| `MAC_CERTIFICATE_PWD` | p12 证书密码（electron-builder `CSC_KEY_PASSWORD` 读取） |
| `APPLE_ID` | Apple ID（notarytool 公证） |
| `APPLE_APP_SPECIFIC_PASSWORD` | App 专用密码（公证） |
| `APPLE_TEAM_ID` | 开发者团队 ID（公证） |

发布工作流（`.github/workflows/release.yml`）流程：

1. 推送 `v*` tag 触发；
2. 三平台（ubuntu / macos / windows）并行构建：`check-ci.sh`（测试）→
   `build-gateway-bundle.sh`（PyInstaller 打包自包含 gateway：Python 运行时 + 全部依赖 +
   技能包 + 配置模板）→ `build-desktop.sh`（electron-builder 构建，extraResources 内置 gateway）；
3. macOS 额外执行：electron-builder 读 `CSC_LINK` / `CSC_KEY_PASSWORD` 导入证书 →
   codesign 签名 → notarytool 公证并 staple（自动完成）；
4. 各平台安装包 + `latest*.yml` 上传为 Actions artifact；
5. `publish` job 汇总全部产物，创建 GitHub Release（自动生成发布说明）。

## 手动发布（不使用一键脚本）

```bash
# 1. 同步版本号并本地校验
bash scripts/check-release.sh

# 2. 提交并打 tag
git add -A
git commit -m "chore: release v0.1.0"
git tag -a v0.1.0 -m "KStock v0.1.0"

# 3. 推送，触发 GitHub Actions Release 工作流
git push origin main
git push origin v0.1.0
```

## 发布后检查

- 查看构建进度：`./build-release.sh --watch`
- 下载安装包：`https://github.com/kkutysllb/KStock/releases/tag/<tag>`
- macOS 验证签名：`codesign -dv <KStock.app>`、`spctl -a -vv <KStock.app>`

## 本地发布预检

```bash
node scripts/audit.mjs         # 审计三门 + 两报告（发版前置）
bash scripts/prepush.sh        # 全仓库 pre-push 门（审计 + 引擎契约 + 资源契约 + CI 车道）
bash scripts/check-ci.sh       # 单独跑 CI 车道（插件构建 + 类型 + 单测）
bash scripts/build-desktop.sh  # 本机桌面构建（产物不签名）
```

> 引擎克隆是可弃的（`bash scripts/engine-bootstrap.sh --prune` 释放约 3.5 GB）：
> 跑门禁或发布前先 `bash scripts/engine-bootstrap.sh --full` 重新引导（依赖 + 产物 + 闭包门禁）。
