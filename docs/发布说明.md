# 发布说明

## 一键发布

在项目根目录执行：

```bash
./build-release.sh v0.1.0
```

脚本会自动完成：

1. 校验版本号格式（`vX.Y.Z`）、git 工作区状态、当前分支与远端同步情况；
2. 同步版本号到 `package.json` / `apps/desktop/package.json` / `pyproject.toml`；
3. 本地预检（`check-ci.sh` 全量测试 + 类型检查，再执行本机桌面构建）；
4. 生成发布说明（自上一 tag 以来的提交）；
5. 提交版本号、打 annotated tag、推送 `main` 与 tag；
6. 推送 tag 触发 GitHub Actions `Release` 工作流，构建完成后安装包自动上传到 GitHub Release。

常用参数：

| 参数 | 说明 |
|------|------|
| `--skip-check` | 跳过本地预检（构建交给 CI） |
| `--no-push` | 只提交 + 打 tag，不推送 |
| `--force` | 工作区有未提交改动 / 本地落后远端时仍继续 |
| `--watch` | 监控最近一次 Release workflow 运行结果（需已安装 GitHub CLI） |

## 发布产物

| 平台 | 产物 | 签名 |
|------|------|------|
| macOS (Apple Silicon) | `.dmg` / `-mac.zip`（updater） | Developer ID 签名 + notarytool 公证（staple） |
| Windows (x64) | `.exe`（NSIS） | （代码签名证书后续补充） |
| Linux (x64) | `.deb` | （无额外签名） |

> 发布仅覆盖上述三个平台，不提供 macOS Intel 产物；Linux 不打 AppImage
> （linuxdeploy 在 GitHub Actions 上不稳定，v0.1.1 已确认 deb 可用）。

## 自动更新（electron-updater）

桌面端内置自动更新，真正开箱即用：

- 侧边栏用户位置右侧的**隐藏下载图标**：默认不显示，检测到新版本时出现（带红色角标），
  悬停提示版本号；点击后下载更新（下载中图标旋转并提示已下载体积），
  下载完成后自动重启并安装；失败可点击重试。
- 更新源：GitHub Release 的 `latest-mac.yml` / `latest.yml` / `latest-linux.yml`
  （electron-builder 构建时自动生成，各平台独立一份），`electron-updater` 读取后下载差分包。
- 产物形态：macOS `.zip` / Windows `.exe`（NSIS）/ Linux `.deb`（含 blockmap 增量更新）。

## 签名与安全配置

macOS 签名与公证使用仓库 Secrets（已在 GitHub 仓库配置完成）：

| Secret | 用途 |
|--------|------|
| `MAC_CERTIFICATE` | Apple Developer ID 证书（base64 编码的 p12，electron-builder `CSC_LINK` 读取） |
| `MAC_CERTIFICATE_PWD` | p12 证书密码（electron-builder `CSC_KEY_PASSWORD` 读取） |
| `APPLE_ID` | Apple ID（notarytool 公证） |
| `APPLE_APP_SPECIFIC_PASSWORD` | App 专用密码（公证） |
| `APPLE_TEAM_ID` | 开发者团队 ID（公证） |

发布工作流（`.github/workflows/release.yml`）流程：

1. 推送 `v*` tag 触发；
2. 三平台（ubuntu / macos / windows）并行构建：`check-ci.sh`（测试）→
   `build-gateway-bundle.sh`（PyInstaller 打包自包含 gateway：Python 运行时 + 全部依赖 +
   技能包 + 配置模板）→ `build-desktop.sh`（electron-builder 构建，extraResources 内置 gateway）；
3. macOS 额外执行：electron-builder 读 `CSC_LINK` / `CSC_KEY_PASSWORD` 导入证书 →
   codesign 签名 → notarytool 公证并 staple（自动完成）；
4. 各平台安装包 + `latest*.yml` 上传为 Actions artifact；
5. `publish` job 汇总全部产物，创建 GitHub Release（自动生成发布说明）。

## 手动发布（不使用一键脚本）

```bash
# 1. 同步版本号并本地校验
bash scripts/check-release.sh

# 2. 提交并打 tag
git add -A
git commit -m "chore: release v0.1.0"
git tag -a v0.1.0 -m "KStock v0.1.0"

# 3. 推送，触发 GitHub Actions Release 工作流
git push origin main
git push origin v0.1.0
```

## 发布后检查

- 查看构建进度：`./build-release.sh --watch`
- 下载安装包：`https://github.com/kkutysllb/KStock/releases/tag/<tag>`
- macOS 验证签名：`codesign -dv <KStock.app>`、`spctl -a -vv <KStock.app>`

## 本地发布预检

```bash
bash scripts/check-ci.sh       # 测试 + 类型检查
bash scripts/build-desktop.sh  # 本机桌面构建（产物不签名）
```
