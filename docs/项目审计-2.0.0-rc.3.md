## 一、发版门禁（本版新增，对齐 KCoder）

| # | KCoder 发版要求 | 本仓落点 | 失败行为 |
|---|-----------------|----------|----------|
| 1 | `release/<tag>.md` 发布说明 | `build-release.sh`（原有） | 缺失拒绝（`--allow-missing-notes` 应急） |
| 2 | `release/audit-<tag>.md` 审计报告 | **本文件** + `build-release.sh` 新增 `require_audit_report()` | 缺失拒绝，**无跳过开关** |
| 3 | `audit`：TYPECHECK / LINT / SECURITY 三门 + 死代码 / 冗余依赖两报告 | **新增 `scripts/audit.mjs`** | 任一硬门失败即退出 1 |
| 4 | `prepush`：审计 + 插件闸 + 版本线 + 冒烟 + 全量构建 | **新增 `scripts/prepush.sh`**（`build-release.sh` 的 `run_checks` 改为调它） | 非零退出即中止 |
| 5 | tag 冲突 / 远程 tag / 落后 origin | `build-release.sh`（原有） | 中止 |
| 6 | 打包链签名公证 fail-closed + 产物门禁 | `check-release.sh` + `verify-desktop-artifacts.sh`（原有，CI 执行） | 构建失败 / 资产不符 |
| 7 | 发布后资产交叉比对 | `build-release.sh --watch`（原有） | 中止 |

**与 KCoder 的对应差异**（有意为之，非缺口）：

- KCoder 的 `patchgate`（插件热补丁链）在本仓没有对应形态，其守卫面由
  `scripts/verify_package_resources.py`（插件清单 / bundle patch / 技能接线 / 无遗留模块）承担；
- KCoder 的 `bundleline`（内置插件版本线）在本仓对应引擎契约的「产品提交数 == 7、
  集成分支无裸提交」断言；
- 本仓没有「本机签名打包」链（打包交给 CI 三平台），因此 `prepush` 不触发 electron-builder。

## 二、安全

### S-1〔核查 · 通过〕生产依赖漏洞清零

- `pnpm audit --prod --audit-level high`：**root 工作区**（含 `apps/desktop`）与
  **kstock 工作区**（独立 lock、自带 pnpm 11.7.0）均 `No known vulnerabilities found`。
- rc.2 登记的 HIGH 项（electron-updater → js-yaml `GHSA-2883-xcg3-v3hh`）复核：
  `pnpm -C apps/desktop why js-yaml` → 全部解析为 **5.4.2**；`pnpm-lock.yaml` 的
  `overrides` 段保留 `js-yaml@<4.3.2: '>=4.3.2'`；本版新增 devDependencies 后重跑
  `pnpm install --lockfile-only`，**js-yaml 仍为 5.4.2**（未被重新解析回 4.3.1）。

### S-2〔风险登记 · 未影响本版〕`package.json` 的 `pnpm.overrides` 已进入弃用通道

- **现象**：本机 pnpm（9.15.0）在每次调用时打印
  `The "pnpm" field in package.json is no longer read by pnpm. The following keys were ignored: "pnpm.overrides"`；
  v10+ 已把设置迁到 `pnpm-workspace.yaml`。
- **影响评估**：本版**无实际影响**——lockfile 已固化解析（5.4.2）且 CI 走
  `pnpm install --frozen-lockfile`，不会重新解析；实测 `--lockfile-only` 刷新后仍为 5.4.2。
- **后续动作（rc.4 候选）**：把 override 迁到 `pnpm-workspace.yaml` 的 `overrides:`，
  迁完在 pnpm 9.15 / 11.7 两条路径各验一次，再删 `package.json` 里的字段。

### S-3〔核查 · 通过〕发布链 fail-closed 语义未被削弱

- macOS 签名 + 公证凭据缺失时 `check-release.sh` 在构建前拦截（不依赖 electron-builder 的 notarize 行为）；
- 产物层 V1–V8 门禁（`verify-desktop-artifacts.sh`）与 CI 收集产物前调用的是同一文件；
- 本版新增的门（审计报告 + prepush）**只加不减**：`--skip-checks` 可跳过的仍只有预检一项，
  发布说明与审计报告两个硬门不可跳过。

## 三、死代码与冗余依赖（报告项处置）

| 编号 | 发现 | 处置 | 理由 |
|------|------|------|------|
| D-1 | `apps/desktop/electron/lib/chrome.ts:36 TITLEBAR_PAD_RIGHT`（全仓引用 0 次） | **已删除** | 真死导出；真实值在 `kstock/client-brand/src/client/windowChrome.ts:169 CAPTION_BUTTONS_WIDTH = 138`，Electron 侧那份是 headerRight 移除后的残留副本（双事实源漂移风险） |
| D-2 | `kstock/accounts/src/validation.ts:12/15 MIN_USERNAME_LENGTH`、`MAX_USERNAME_LENGTH`（各 1 次引用＝仅声明处） | **豁免** | 与在用的 `MIN_PASSWORD_LENGTH` 同族的口径常量，保留为账户策略的对外契约面（UI 镜像校验）；价值大于删除 |
| D-3 | `kstock/web` 声明未用依赖 `@kstock/client-brand` | **豁免** | **depcheck 假阳性**：该包经 `kstock/web/cordis.patch.yml:123` 挂载、`file:` 链接引入，静态 import 视角看不见 |

- DEAD EXPORTS 报告口径：ts-prune 对本仓 3 个 project 共报 **45 项候选**，经「全仓字面引用
  交叉核对」后剩 **3 项**——37 项为跨包/引擎侧消费者（单 project ts-prune 看不见），
  5 项为插件生命周期入口（`apply` / `inject` / `name`，宿主按名调用）按类豁免。
  这比 KCoder 的静态豁免表更准（本仓 UI 包之间大量经 tsconfig 别名互相消费）。
