# 用户数据空间组织设计

## 目标

KStock 正式桌面端必须把用户数据放到用户主目录 `~/.kstock`，而不是仓库内的 `.kstock` 或系统应用数据目录。QiLin 仍然作为运行时真源，负责用户、线程、sandbox、运行记录、消息事件和文件虚拟路径；KStock 只增加产品层索引，用来表达项目、报告、标签、收藏、最近打开和界面状态。

这份设计采用“QiLin 运行真源 + KStock 产品索引层”的混合方案。

## 设计原则

- 不污染 QiLin / KSkills 上游仓库：运行数据、用户配置、日志和缓存全部落在 KStock 用户数据目录。
- 不重复实现 QiLin 已有能力：线程、运行、消息事件、上传、产物路径、用户隔离优先复用 QiLin。
- 数据根目录统一为 `~/.kstock`：gateway 入口（`scripts/run_gateway.py`）解析默认根，Tauri/Rust 宿主或命令行可通过 `KSTOCK_APP_DATA_DIR` 显式覆盖。
- sidecar 统一建立用户上下文：所有 QiLin 调用都在稳定 `user_id` 下执行，避免数据库记录和文件路径分别落到不同用户。
- 研究 / 分析 / 报告优先：目录和索引围绕任务、数据输入、研究过程、报告产物组织，不引入 coding 产品语义。

## 跨平台数据根目录

用户数据根目录全平台统一为 `~/.kstock`，由 `scripts/run_gateway.py` 解析：

- 默认：`~/.kstock`（macOS / Windows / Linux 统一，无空格、可见可备份）
- 显式覆盖：`KSTOCK_APP_DATA_DIR` 环境变量（Tauri 宿主 / 命令行调试）

选择 `~/.kstock` 而非系统应用数据目录（Application Support）的原因：

- 避免 macOS `Application Support` 含空格导致沙箱 bash 路径替换被 shell 拆词（历史故障：`ls /mnt/user-data/workspace/` 实际列出 `.../Library/Application` 空目录，表现为「工作目录为空」）
- 数据可见、可备份、跨机器拷贝简单
- 与仓库内 `.kstock/cache`（调试缓存）区分：产品数据一律在主目录

历史版本（v1）数据位于系统应用数据目录，由 `_migrate_legacy_data_root` 在 gateway 启动时一次性迁移到 `~/.kstock`：

- macOS：`~/Library/Application Support/KStock`
- Windows：`%APPDATA%\KStock`
- Linux：`~/.local/share/KStock`

迁移条件：新根不存在且旧根含 `config/` 或 `runtime/`；迁移后同步重写 `qilin.runtime.yaml` 的 `database.sqlite_dir`（旧配置指向旧根的绝对路径，不重写会继续写旧位置）。

## 目录结构

```text
KStock 数据根目录/
  config/
    kstock.settings.json
    qilin.runtime.yaml
    models.yaml
    secrets.env
  runtime/
    qilin/
      data/
        qilin.db
      users/
        {user_id}/
          memory.json
          agents/
          skills/
            custom/
          threads/
            {thread_id}/
              user-data/
                workspace/
                uploads/
                outputs/
              acp-workspace/
  product/
    kstock.db
    exports/
    report-index/
  cache/
    market-data/
    skill-scan/
    thumbnails/
  logs/
    sidecar.log
    engine.log
  backups/
```

`runtime/qilin` 是 QiLin 的 `QILIN_HOME`。QiLin 线程目录继续作为真实工作目录，sandbox 中仍映射为 `/mnt/user-data`：

- `/mnt/user-data/workspace`：任务工作区、临时分析脚本、结构化中间结果。
- `/mnt/user-data/uploads`：用户上传的财报、研报、CSV、Excel、图片等输入。
- `/mnt/user-data/outputs`：分析结果、图表、报告、导出文件。
- `/mnt/acp-workspace`：QiLin ACP 相关隔离工作区。

## 配置生成

发布包内的 `config/qilin.config.yaml` 作为模板，不直接写用户运行数据路径。sidecar 启动时生成：

`{KSTOCK_APP_DATA_DIR}/config/qilin.runtime.yaml`

运行时环境变量：

```text
QILIN_PROJECT_ROOT=<发布包资源根或开发仓库根>
QILIN_CONFIG_PATH=<KStock 数据根目录>/config/qilin.runtime.yaml
QILIN_HOME=<KStock 数据根目录>/runtime/qilin
QILIN_SKILLS_PATH=<发布包资源根>/vendor/skills
KSTOCK_APP_DATA_DIR=<KStock 数据根目录>
```

`qilin.runtime.yaml` 必须显式写入数据库配置：

```yaml
database:
  backend: sqlite
  sqlite_dir: <KStock 数据根目录>/runtime/qilin/data

run_events:
  backend: db

skills:
  root: <发布包资源根>/vendor/skills

sandbox:
  use: qilin.sandbox.local:LocalSandboxProvider
  allow_host_bash: false
```

模型配置由 KStock 设置页写入 `models.yaml` 或合并进 `qilin.runtime.yaml`。带 QiLin 补丁适配的模型模板继续保留 provider 字段，例如 `qilin.models.patched_deepseek:PatchedChatDeepSeek`。

## 用户身份

V1 使用本机默认用户，生成稳定 ID：

```text
local-{机器安装标识短哈希}
```

`{KSTOCK_APP_DATA_DIR}/config/kstock.settings.json` 保存：

```json
{
  "activeUserId": "local-xxxx",
  "schemaVersion": 1
}
```

未来登录/注册启用后，用户 ID 可以迁移为账号 ID，但必须保留旧本地用户目录映射。迁移时只更新 KStock 产品索引和 QiLin `threads_meta.user_id`，不要直接改上游代码。

sidecar 每个请求入口都要设置 QiLin `CurrentUser` 上下文，并在 finally 中 reset。原因是 QiLin repository 的 `AUTO` 用户解析依赖 ContextVar；而部分文件路径函数未设置用户时会落到 `default`。KStock 不能让同一次任务同时写入 `default` 文件目录和另一个数据库用户。

## 数据库边界

QiLin SQLite：

`runtime/qilin/data/qilin.db`

归 QiLin 管理，包含：

- `users`
- `threads_meta`
- `runs`
- `run_events`
- `feedback`
- `agents`
- scheduled task 相关表

KStock SQLite：

`product/kstock.db`

归 KStock 管理，包含产品索引，不保存 QiLin 已有运行真源：

- `projects`：研究项目，例如“新能源行业跟踪”。
- `project_threads`：项目和 QiLin thread 的关联。
- `report_assets`：报告产物索引，指向 QiLin outputs 虚拟路径或宿主绝对路径。
- `task_tags`：标签、收藏、归档状态。
- `recent_items`：最近打开。
- `ui_state`：侧边栏折叠、设置页偏好等。

KStock 读取任务历史时，以 QiLin `threads_meta` 和 `run_events` 为主，以 `product/kstock.db` 补充产品视图。

## sidecar 协议

下一阶段 sidecar 不再只支持 `health`，需要扩展为稳定 JSON 行协议：

- `workspace.init`：初始化数据根目录、生成运行时配置、创建默认用户。
- `workspace.info`：返回数据目录、引擎目录、数据库路径、技能根目录、当前用户。
- `thread.create`：创建 QiLin thread metadata，建立线程目录，可选绑定项目。
- `thread.list`：合并 QiLin `threads_meta` 和 KStock 产品索引。
- `thread.get`：读取线程消息、上传文件、输出产物、运行状态。
- `run.start`：对指定 thread 调用 QiLinClient.stream，返回流式事件。
- `run.cancel`：取消或中断当前运行。
- `file.upload`：复用 QiLin upload manager 写入 `/mnt/user-data/uploads`。
- `artifact.list`：扫描 `/mnt/user-data/outputs` 并回填 report index。
- `artifact.open`：返回宿主文件路径或安全读取内容。
- `project.create` / `project.list` / `project.update`：KStock 产品层项目管理。

协议返回中统一携带：

```json
{
  "userId": "local-xxxx",
  "threadId": "thread_xxxx",
  "paths": {
    "virtual": "/mnt/user-data/outputs/report.md",
    "host": ".../runtime/qilin/users/local-xxxx/threads/thread_xxxx/user-data/outputs/report.md"
  }
}
```

## 报告与产物

报告文件的真实产出位置是 QiLin thread outputs：

```text
runtime/qilin/users/{user_id}/threads/{thread_id}/user-data/outputs/
```

KStock `report_assets` 只保存索引：

- report id
- thread id
- project id
- 标题
- 文件名
- 虚拟路径
- 宿主路径
- MIME 类型
- 创建时间
- 最后打开时间

这样报告既能被 QiLin sandbox 继续访问，也能被桌面端作为产品资产展示、预览、导出和归档。

## 上游同步边界

`vendor/qilin` 和 `vendor/skills` 是发布包资源。它们通过 `scripts/sync_upstreams.py` 从本地或 GitHub 同步，并由 `upstream.lock.json` 跟踪版本。

禁止把以下内容写入 `vendor`：

- 用户设置
- 模型密钥
- 线程历史
- 上传文件
- 报告产物
- 缓存数据
- 本地日志

QiLin 上游升级时，KStock 只更新内置快照和兼容层。若需要适配 KStock 数据空间，优先在 sidecar 层处理，不直接修改上游仓库。确实需要引擎级修复时，应在本地产品先 patch vendor，再单独向 QiLin 上游提交独立 PR。

## 迁移策略

历史版本（v1）数据位于系统应用数据目录（macOS `~/Library/Application Support/KStock`）。v2 起数据根统一为 `~/.kstock`，gateway 启动时自动迁移：

1. 检查 `~/.kstock` 是否已存在——已存在则跳过（绝不覆盖新数据）。
2. 检查 v1 旧根（跨平台候选）是否存在且含 `config/` 或 `runtime/`（排除空目录与调试残留）。
3. 唯一旧根 → `shutil.move` 整体迁移（同卷 rename，原子且快）；跨卷失败时回退拷贝 + 删除。
4. 迁移后重写 `qilin.runtime.yaml` 的 `database.sqlite_dir` 为新根（旧配置指向旧根的绝对路径）。
5. 存在多个旧根时告警并跳过，由用户手动处理。

迁移幂等：目标已存在 / 无旧目录时直接返回，可安全重复执行。

## 验证标准

实现完成后必须验证：

- macOS / Windows / Linux 构建时不依赖仓库内 `.kstock`。
- Tauri dev 和 build 都能把 app data 目录传给 sidecar。
- `QILIN_HOME` 指向 `runtime/qilin`。
- `qilin.runtime.yaml` 中 SQLite 路径为绝对路径。
- 首次启动能创建默认用户和目录。
- 创建线程后出现 QiLin 原生 thread 目录。
- 上传文件进入 `/mnt/user-data/uploads` 对应宿主目录。
- 报告文件进入 `/mnt/user-data/outputs` 对应宿主目录。
- 重启桌面端后线程历史、消息、报告索引仍可读取。
- 上游同步脚本不会写入用户数据目录。

## 实施顺序

1. 在 Tauri/Rust 层解析 app data 目录，并暴露给 sidecar。
2. 在 sidecar 增加 `KStockDataSpace` 模块，负责目录创建、配置生成、默认用户和迁移。
3. 修改 `SidecarConfig`，让正式默认值来自 `KSTOCK_APP_DATA_DIR`，开发模式保留 `.kstock` fallback。
4. 启动 QiLin 前生成 `qilin.runtime.yaml`，显式配置 SQLite、run events、skills、sandbox。
5. 增加 QiLin 用户上下文包装器，所有业务请求都在当前 `user_id` 下执行。
6. 扩展 sidecar 协议，实现 workspace/thread/run/file/artifact 的最小闭环。
7. 增加 KStock 产品索引数据库，只保存项目、报告、标签和 UI 状态。
8. 补充跨平台测试、sidecar 单测、Tauri 冒烟和打包检查。

## 结论

KStock 不应把用户数据继续放在仓库内，也不应绕过 QiLin 重做任务运行存储。正确边界是：QiLin 负责运行时真源，KStock 负责桌面产品体验和索引视图。这个设计能支持正式打包、跨平台运行、上游同步、不污染上游，也为后续登录、云同步、多用户和高级量化任务留下扩展空间。
