### 关键修复：secrets.env 与引擎热重载

引擎（vendor/qilin）基于 mtime 检测 `qilin.runtime.yaml` 变化并自动重载，重载时通过 `AppConfig.resolve_env_variables` 从进程 `os.environ` 解析 `$KEY` 引用。初版实现把 API key 写进了 secrets.env 文件、却从未加载到 gateway 进程环境，导致 POST 创建含 api_key 的模型后 GET 返回 500（`ValueError: Environment variable KSTOCK_MODEL_X_KEY not found`）。

修复（commit 6bfc835）：

- `run_gateway.py` 新增 `_load_secrets_env`，启动时把已有 secrets.env 加载到 `os.environ`（日志打印加载数量）；
- `kstock_models.upsert_secret` / `remove_secret` 同步更新 `os.environ`，使运行时增删即时生效，引擎下次热重载即可解析新引用，无需重启 gateway。

### 关键发现：真实 SSE 协议

Task 0 实测纠正了 plan 初稿的协议假设：

- 路径是 `/api/threads`（非 `/api/v1/threads`）
- event 名是 `messages`（非 `messages-tuple`）；`messages` 的 data 是数组 `[msg_dict, metadata_dict]`，取 `data[0]`
- `msg_dict.type` 枚举：
  - 非流式快照：`human` / `ai` / `tool` / `system`（非 user/assistant）
  - **流式 chunk**（全 langchain provider）：`AIMessageChunk` / `ToolMessageChunk` / `HumanMessageChunk` / `SystemMessageChunk`。最初只认 `ai`，MiniMax 流式文本不渲染；后重构为**语义优先路由**——不依赖 type 字符串，按语义特征（tool_call_id / reasoning_content / content / tool_calls / usage_metadata）路由，所有 provider 及未来新增自动适配
- system-reminder 带 `additional_kwargs.hide_from_ui=true`，前端跳过
- 引擎把 provider error（如 API key 无效）包装成带 `qilin_error_fallback=true` 的 ai message（而非 SSE error 事件）
- **MiniMax api_base**：国内版 `api.minimaxi.com/v1`，国际版 `api.minimax.io/v1`；key 与域名不匹配会报 AuthenticationError 401

### 架构决策

- **前端直连引擎网关**（零新 BFF）：fetch POST + ReadableStream 读 SSE，不用 EventSource（后者不支持 CSRF header）
- **localStorage 会话真源**：ChatSession 加 `threadId`，首次发消息时 `POST /threads` 创建并绑定
- **RunContext 注入**：`model_name` + `thinking_enabled`（`supports_thinking`）+ `reasoning_effort`（按需）

### 关键修复一：authorization UI 防护（enabled 依赖 provider）

**问题**：用户在 UI 启用「资源授权」但未配 provider，导致 `authorization.enabled=true`
且 `provider=null` 的自相矛盾状态。gateway 每次路由请求报
`ValueError: authorization.enabled is true but no provider is configured`，
日志 WARNING 刷屏。

**修复**（两层）：

1. 止血：把用户 `runtime.yaml` 的 `authorization.enabled` 改回 false；
2. UI 防护：`GuardrailsSettings` 根据 `provider` 状态动态生成字段——provider 为 null
   时，「启用资源授权」开关灰色禁用，下方显示警告「需先在 runtime.yaml 配置
   `authorization.provider.use`才能启用」。

实现要点：
- `RuntimeConfigCard.tsx` 的 `FieldDef` 扩展 `disabled?` + `disabledReason?` 两个
  可选字段，作为通用 UI 能力（不限于 authorization）；
- `FieldRenderer` 在全部 7 种 input 类型（boolean / select / number / string /
  nullable-string / string-list / context-size）传递 `disabled` 属性；
- CSS `.rcf-field.is-disabled`（opacity 0.6）+ `.rcf-disabled-reason`（amber-500
  警告色）。

### 关键修复二：runtime.yaml tools 段增量合并（老用户 yaml 同步）

**问题**：agent 被问「今天 A 股有哪些新闻」时回复「不支持实时网页搜索」，但
`config/qilin.config.yaml` 里明明挂了金融搜索工具。gateway 日志显示
`Total tools loaded: 0`。

**根因**：用户 `runtime.yaml` 是早期版本首次启动时从模板复制的，那时模板还没
`tools:` 段。`_generate_runtime_config` 的策略是「已存在则直接 return，绝不
覆盖」（为了避免覆盖用户持久化的 models / memory / database 配置），但这导致
模板后续新增的 `tools` 段永远到不了老用户 yaml，`config.tools` 为空，LLM 看不
到任何工具。

**修复**：把「已存在则 return」改为「已存在则增量合并模板的 `tools` 段」。
`tools` 段是产品级配置（不是用户级），覆盖安全；其他段仍原样保留。当
`existing.tools != template.tools` 时才写入，保证幂等。

涉及文件：
- `scripts/run_gateway.py` — `_generate_runtime_config` 增量合并逻辑；
- `tests/test_run_gateway.py` — 3 个新回归测试（老 yaml 缺 tools 段 / 模板升级
  后旧引用被覆盖 / tools 已同步时幂等）+ 1 个端到端测试补 tools 断言。
