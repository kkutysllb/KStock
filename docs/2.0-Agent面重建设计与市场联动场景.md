# 2.0 Agent 面重建设计与市场联动场景（第一块）

> 本文是 KStock 2.0（QiLin 3.x 插件平台重构）的 Agent 面重建设计，并落地
> 第一个场景：**市场联动分析**。前身复盘见 [2.0-特性差异与迁移说明](2.0-特性差异与迁移说明.md)。

## 1. 背景：换版复盘结论

2.0 把引擎从「vendored QiLin 2.x Python + monkey-patch」换成 QiLin 3.x
TS monorepo（一切皆插件）。逐层核查后的记分板：

| 1.x 能力 | 3.x 插件形态 | 2.0 现状 |
|---|---|---|
| 32 个投研技能 | `@qilin/skill-filesystem`（provider）+ `@qilin/tool-skill`（consumer），`KSTOCK_SKILLS_DIR` 全局层挂载 | ✅ 已落地 |
| 四库侧栏 UI（策略/因子/选股/报告） | slots 插件（`main` 面板 + `sidebar.panellist`） | ✅ 已落地（`@kstock/quant-*` 四包） |
| 数据 API `/kstock-api/*` | `@kstock/quant` 宿主插件 | ✅ 已落地 |
| 账户 / 品牌 / 落地页 | accounts fork + client-brand + web 插件 | ✅ 已落地 |
| lead_soul.md 运行守则（soul-v7） | persona（preset 行，shadow 部署级人格） | ❌ 仅两句话人格（`cordis.patch.yml` system-prompt 行） |
| 六角色子代理体系（market-data-analyst 等） | agent preset / 委派 per-child persona + toolFilter | ❌ 未建 |
| 场景编排（市场联动/可转债/期指专题） | 场景技能 + workflow 模板 | ❌ 未建 |

结论：**UI 面与技能面用户看得见的都在；丢失全部在 agent 面**（人格、
分派纪律、场景编排），症状即「产品看起来没缺什么，但对话变笨了」。
1.x 的 `config/lead_soul.md` 与 `config/qilin.config.yaml` 深度绑定旧引擎
工具面（/mnt/user-data 虚拟路径、render_html_report 工具、read_file 激活
密钥机制），不可原样回迁，必须按 3.x 工具面重写。

## 2. QiLin 3.x 插件面映射（「一切皆插件」）

| 能力 | 插件化载体 | 关键机制（本设计依赖） |
|---|---|---|
| 技能 | `ctx.skills` 分层注册表 | host 全局层（KStock 精选技能经 `KSTOCK_SKILLS_DIR`）+ preset 层合并；模型经 `skill({name})` 工具按需加载 |
| 提示词 | `@qilin/persona`（preset 内的行） | per-preset shadow 部署级人格；`{{model}}`/`{{cwd}}` 模板插值 |
| 场景/角色 | **agent preset 目录**（`preset.yml` + `agent.cordis.yml`） | agent 面整体移到 preset 后：web 表面禁用宿主 tool-bash/tool-fs/tool-skill 等行，由 preset 的 standing composition 挂载（isolate realm，per-session 隔离） |
| 委派 | `@qilin/tool-subagent`（spawn/fork provider） | per-child persona / toolFilter / outputSchema / agentOptions；continuable 后台子代理 + steer 消息 |
| 流程 | `@qilin/workflow-ptc` + `@qilin/tool-workflow` | 模型写编排脚本 `agent()/pipeline()/parallel()/phase()` 扇出子代理 |
| UI | `qilin.client` 行 + slots | `main` keyed 面板 + `sidebar.panellist` 导航（四库已用） |

preset 的发现由 `@qilin/agent-presets` 配置：`default`（缺省 preset id）+
`roots`（扫描根，`system`/`user` 信任级）。出厂 `standard` preset 是功能
完整的编码 Agent（bash/fs/skills/goal/plan/compaction/subagent/workflow/
todo/web/present），本设计即 fork 它改人格。

## 3. 重建架构总览（三层，渐进落地）

```
┌─ L1 人格层：kstock-investor preset（本次落地）
│    persona 行 = lead_soul v2「最小完整版」：技能/委派/数据/交付四纪律
│    工具面 = fork standard（bash、fs、skill、subagent、workflow、todo…）
│    挂载 = KSTOCK_PRESETS_DIR（env）→ agent-presets roots → default
├─ L2 场景层：场景技能（本次落地第一个：market-linkage）
│    每个场景一个技能 = 编排手册（触发词、阶段、涉及技能、交付物）
│    按需加载不占常驻上下文；复用 L1 人格中的分派纪律
└─ L3 流程层：workflow 模板（后续）
     固定多阶段扇出（如全维度扫描→并行解读→汇总）固化为 workflow 范式
```

角色 preset（缠论分析师等六角色）暂不单独建 preset：3.x 委派已支持
per-child persona + toolFilter，场景技能在委派 prompt 中内联角色指令即可
达到 1.x 等价语义；待多角色并行成为常态后再评估独立 preset。

## 4. KStock 角色 preset 矩阵（6 个，标准模式为默认基座）

产品结构：出厂 `standard` 保持缺省（默认基座）；6 个 KStock 角色 preset
并列于选择器，用户按任务选用（order 10-15 置于出厂四预设之后）：

| preset | order | 随行技能（manifest 子集） |
|---|---|---|
| market-analysis 市场分析 | 10 | 5 个场景技能 + 联动/期指/期权/ETF/转债引擎 + 宏观指数行业等（22 项） |
| stock-analysis 个股分析 | 11 | 财报/估值/DCF/盈利预测/事件舆情等（15 项） |
| stock-screener 选股专家 | 12 | 选股引擎 + 财务估值因子补充（12 项） |
| chan-theory-expert 缠论专家 | 13 | stock-analysis（缠论脚本）+ 图表（5 项） |
| strategy-research 策略研究 | 14 | 策略/回测/选股/tushare（8 项） |
| factor-mining 因子挖掘 | 15 | 因子/选股/tushare（8 项） |

- 每个 preset：`preset.yml` + `agent.cordis.yml`（fork standard，仅 persona
  （角色职责 + 四纪律）与 skill-filesystem（baseUrl 随行绑定）两行差异）
  + `skills/`（按 [skills.manifest.json](../kstock/presets/skills.manifest.json)
  发布的子集；技能随 preset 走，子代理继承父组合）；
- 挂载：`@kstock/web` 替换 `agent-presets` 行——`default: standard`，
  `roots: [KSTOCK_PRESETS_DIR]`（system 信任级）；宿主层不挂技能行
  （web-app 的禁用即上游设计：presets own local discovery）。

## 5. 市场联动场景技能（`market-linkage`，第一个场景）

1.x 的市场联动 = lead_soul 场景编排 + market-data-analyst 子代理 +
market-linkage-engine 技能（8 维度：主力资金/北向/两融/期指基差/期权
波动率/ETF 份额/Shibor/龙虎榜）。2.0 重建为场景技能：

- **位置**：源码在 `kstock/skills/market-linkage/`（KStock 自有，上游同步
  不覆盖），由 `patch_vendor_skills.py` ensure 进 `vendor/skills/public/`
  并发布进 preset 随行 `skills/`（与 html-report 同机制）；
- **编排三阶段**：
  1. **数据采集**：加载 market-linkage-engine 技能 → 在其目录执行
     `python3 -m market_linkage_engine daily|weekly -f json -o linkage.json`
     （日/周粒度按用户问法选择）；必须用 `-o` 落盘，禁止 shell 重定向；
  2. **分维度解读**（可选）：对期指基差/ETF/宏观维度，`subagent` 并行委派
     补充解读（prompt 要求子代理先 `skill` 加载 futures-analysis /
     etf-analysis / macro-query 再工作）；
  3. **报告交付**：按 html-report 技能契约构造报告 JSON（评分卡 + 8 维
     雷达 + 北向/两融时间序列 + 结论），渲染单文件 HTML，归档报告库
     （`POST /kstock-api/reports`），`present` 呈现。
- **输出纪律**（继承 1.x 口径）：8 维表格数值原样转述不改写；缺失维度标注
  「无数据」及原因；金额口径亿元；结论带综合评分与偏向。

## 6. 挂载与打包链路

```
源码流: vendor/skills（上游同步）──patcher──► vendor/skills/public（最终语料）
        kstock/skills/*（自有：market-linkage / html-report / sandbox-path-guide）
                └──ensure──► vendor/skills/public ──发布──► preset 随行 skills/
dev:    engine.ts 设 KSTOCK_PRESETS_DIR = <repo>/kstock/presets
打包:   build-engine-bundle.sh 拷贝 kstock/presets → resources/engine/presets
        （技能随 preset 走，无独立 skills 目录）
patch:  @kstock/web cordis.patch.yml 替换 agent-presets 行
        （default: kstock-investor | standard，roots: [KSTOCK_PRESETS_DIR]）
会话:   新会话挂 kstock-investor preset → persona 四纪律 + 全套工具面 +
        preset 层技能目录（33 项，含场景技能）可见；子代理继承同一组合
```

技能路径解析口径：`skill` 工具加载结果自带
`Base directory for this skill: <绝对路径>`，文档中的相对路径按该基目录解析；
上游技能文档残留的旧绝对路径（`/mnt/skills/...`）不做文本改写，运行时以
基目录为准自我纠正（sandbox-path-guide 2.0 承载此口径）。

密钥口径：1.x 的「read_file 激活技能绑定 required-secrets」机制已不存在；
2.0 由 Electron 壳把老 `secrets.env`（TUSHARE_TOKEN / IWENCAI_API_KEY 等）
在启动引擎前并入环境（不覆盖已有键），技能脚本经 bash 继承。

## 9. 补遗：技能分发架构修正 + 首轮实测反馈修复

**架构修正（复盘记录）**：第一版实现（宿主全局层 + KSTOCK_SKILLS_DIR +
corpus 文本改写补丁）与 web-app「presets own local discovery」设计相逆，
且路径解析本就内建于 skill 工具加载结果（`Base directory for this skill` +
相对路径按基目录解析）。修正为技能随 preset 分发（cordis 样板 baseUrl
模式），corpus 补丁移除、vendor 回上游原文；行情缓存 `market_data_cache.py`
改探测式目录解析（宿主可写→临时区保底）并修复越界写崩溃；preset 发布
排除 build/__pycache__ 残留。

**首轮实测反馈修复（同批）**：

1. **未登录直进 workspace**（三重叠加根因）：① profile 插件符号链接按
   目录名误建（`@kstock/accounts` ≠ 包名 `@kstock/accounts-local`）→
   accounts 插件「failed to import」→ 登录/注册/会话门整面静默失效；
   ② 壳捕获引擎 stdout 的 token URL 装进主窗口（上游本地信任机制），
   绕过（已失效的）账户门直进工作台；③ bcryptjs 外置依赖加固为内联
   （noExternal）+ 裸内建导入补 `node:` 前缀（SEA internal loader 不认
   裸名）。修复后冒烟全绿：未登录 `/workspace` → 302 回 landing，
   `/api/auth/status` 正常 JSON，首启注册/登录/带 cookie 访问全链通；
2. **语言菜单四项**：client-brand 曾用 addLanguage 注册 kstock-zh/kstock-en
   新语言（菜单多两项且缺键走 fallback 链）→ 移除全部语言与字典注册
   （上游 locale.register 对同一 namespace+locale 重复注册直接抛错，覆写
   官方字典会撞车崩溃），仅保留「未显式选择语言时默认中文」；品牌呈现
   收敛到品牌槽位（见 §10）；
3. **preset 结构**：kstock-investor 单预设 → standard 默认基座 + 6 角色
   preset 矩阵（见 §4），市场联动降位为市场分析预设下的场景之一。

## 11. 补遗三：场景技能操作化深化（股指期货 / 期指期权联动）

首批 5 个场景技能中仅市场联动经过端到端实测打磨；本批把
index-futures-theme 与 option-futures-linkage-theme 补齐到同等操作深度
（精确命令、落盘纪律、JSON 结构、报告契约），其余场景同法跟进：

1. **引擎落盘契约实测**（四入口全验证）：futures-analysis 日/周引擎在
   `--json` 前有一行无条件采集日志（stdout 污染），必须
   `sed -n '/^{/,$p'` 截取后落盘；option-futures-linkage 日/周引擎的
   进度日志被 `if not args.json` guard，`--json` 输出干净、可直接
   `>` 重定向。两类纪律分别写入对应场景手册，禁止裸重定向；
2. **JSON 结构写入手册**：futures = `symbols[品种].{price, contango,
   holding, contracts}` + `composite.{avg_score(0-100), market_env,
   divergence_signal, suggestions}`；option-futures = `symbols[品种].
   {option, futures, linkage}`（direction 五档 + 五维评分 -6..+6）+
   `composite.{avg_score, market_env, symbol_scores}`；
3. **交叉层明确用法**：options-volatility 是计算器非取数器（把联动
   引擎输出的 ATM IV 喂 `--action iv-rv / regime`）；hithink-futures
   问财查询需 IWENCAI_API_KEY，缺则跳过并注明；futures-analysis
   `--type holding` 局部口径仅用于单维追问，不得冒充专题全量；
4. **报告契约对齐 market-linkage**：评分卡 + 具体图表类型（基差率
   line / 多空持仓 bar / 联动评分 bar / PCR×净持仓对照）+ 分节正文 +
   风险提示与数据来源 + `render_report.py` 渲染 + `POST
   /kstock-api/reports` 归档 + present。

## 12. 补遗四：工作区产物分区纪律（scripts / data / reports）

工作区直接操作模式实测后，产物散落工作区根（linkage.json、report.json、
market-linkage.html 混作一团）。本批把分区纪律写进技能层并全链路实测：

1. **权威落点 sandbox-path-guide（2.1.0）**（所有 preset 都加载）：新增
   「工作区目录布局」节——`scripts/` 任务自建脚本、`data/` 引擎输出与
   中间数据、`reports/` 报告 JSON 与渲染 HTML；首个产物落盘前按需

## 21. 补遗十三：Windows 实机验证第一轮反馈修复（启动链两处）

1. **dev/build 脚本跨平台化**（`274bdb7`）：`env -u ELECTRON_RUN_AS_NODE`
   是 Unix env 语法，Windows 下 win-node-env 拼成 `ENV-u` 报「不是内部
   或外部命令」。新增 `apps/desktop/scripts/run.mjs` 启动器：Node 侧
   delete 环境变量后 spawn 转发（Windows .cmd shim 走 shell 解析），
   dev/build 两脚本换用；
2. **profile 插件链接 EPERM**（实机日志：`symlink 'C:\projects\KStock\
   kstock\accounts' -> '...\node_modules\@kstock\accounts-local'`）：
   Windows 真实符号链接需要管理员或开发者模式权限，普通用户 EPERM——
   `ensureKstockProfile` 改为 win32 用 **junction**（目录联接，零特权
   要求，本地目录语义等价；不支持网络路径，dev/打包均为本地目录）。
   连带两修：失效判定改为 readlink 通用判据（junction 的
   `lstat.isSymbolicLink()` 为 false，旧守卫会漏判失效 junction）；
   单包链接失败只跳过该包不再中断整批。macOS 实测：删链接后启动自动
   重建、插件链完整加载。用户侧已创建的半残 profile 无需手动清理——
   stale 检测会自愈补齐；
3. **dev 引擎源码直跑前置缺失静默退出**（实机：`ERR_MODULE_NOT_FOUND
   tsx`，引擎 code=1）：qilin 工作区包 exports 指向 `lib/index.js` 而
   lib 与 node_modules 均不入库——全新检出的 dev 环境必须先
   `qilin-pnpm.sh install` + `build`（或直接建单文件）。此前该缺失让
   引擎子进程在 import 阶段无声退出，报错只有一句「监听端口前退出」。
   现在启动前预检（tsx 存在 + packages/*/lib 已构建），缺任一立即弹
   可操作指引（install → build-engine-bundle.sh 两行命令）。macOS 实测
   两条路径：预检通过时源码直跑引擎完整启动（顺带首次验证了 dev 兜底
   路径本身）；抽走 tsx 后预检准确拦截；
4. **deps.ts Windows 三修**：PYTHONPATH 分隔符写死 `:` 在 Windows 上
   会把多段拼成一个非法路径（正确为 `;`）；python 探测链补 `py -3`
   兜底（python.org 安装器默认只装 py launcher 不进 PATH，极常见）；
   pip 安装失败日志补 signal/error/耗时（此前 `exit null` 无从定位，
  多半是 10 分钟超时被杀——慢网络装 pandas/numpy/matplotlib 可超，
   重跑续传）；
5. **kstock 插件包不在 workspace，构建脚本静默死**（实机：bundle 脚本
   打印「构建 KStock 插件包」后无声返回——`npx tsdown > /dev/null 2>&1`
   + `set -e` 吞掉一切；这些包此前靠手工逐个 install，全新检出必缺
   node_modules）。三修：`pnpm-workspace.yaml` 加 `kstock/*`（注意
   yaml 优先级高于 package.json 的 workspaces 字段——后者一直是被
   忽略的摆设，本次对齐）；`build-engine-bundle.sh` 步骤 1 显式拦截
   缺 node_modules 并在 tsdown 失败时打尾部 20 行；根 `pnpm install`
   一次装齐（lockfile 新增 11 个 kstock importer，`kstock/web →
   @kstock/client-brand` 转 workspace link）。macOS 全链路复验：根
   install → bundle 构建 → check-ci 过；
6. **Windows 构建链三连坑（引擎 exe 已实机构建成功，201MB win-x64）**：
   ① `build-exe-for-python-sdk` 的 `pnpmInvocation` 在 win32 强制要求
   `npm_execpath` 指向 pnpm JS 入口，而 `pnpm exec` 子进程不总继承——
   `qilin-pnpm.sh` 显式导出兜底，Git Bash 下 env 值不做 MSYS 路径转换、
   用 `cygpath -w` 转原生形（`71b5ebf`）；② bundle 步骤 3 的 `python3`
   在 Windows 是 Microsoft Store 桩（存在但一跑即退非零）——新增
   `scripts/python.sh` 解析器（python3 → python → py -3，按**可执行性**
   探测而非 `command -v`），bundle/check-ci/check-release 三处调用点
   统一换用；③ 引擎 exe 已产出并同步 runtime 目录，重跑 bundle 时
   步骤 2 自动跳过（幂等）。protobufjs 的若干 pkg Warning 为上游已知
   噪音，不影响产物；
7. **win-x64 SEA exe 启动即死：staging 缺传递 workspace 包**（实机：
   `runtime-bootstrap.mjs` 的
   `import.meta.resolve('@qilin/sandbox-windows-acl/runner')` 报
   ERR_MODULE_NOT_FOUND——win32 分支在模块加载期即解析，包不在 pkg
   快照）。根因指向 `pnpm deploy --legacy` 在 Windows 把传递 workspace
   依赖留在部署源而未落 staging（上游 `restoreLegacyHoists` 只兜清单
   **直接**依赖，ACL 包是经 `@qilin/sandbox-local` 引入的传递依赖）。
   修法（patcher 补丁 14，vendor 补丁纪律）：`build-exe-for-python-sdk.ts`
   注入 `repairStagedScope`——materialize 后把部署源 @qilin/@deepseek-ai
   两个 workspace scope 下缺失于 staging 的包补拷（只限这两个 scope，
   防 @types/@yao-pkg 等 devDep 灌进 exe），再对补拷包的非 scope 运行时
   依赖（如 koffi）清单驱动补拷。**自带诊断**：修复行打出 repaired 清单
   即坐实假设；无声仍报错则转向 pkg 快照层。重跑需
   `--force-exe-build`（exe 已存在时步骤 2 默认跳过）；
8. **转向 KCoder 路线：单文件 exe 冒烟 + 源码直跑兜底**（实机第二轮，
   结论性转向）。SEA 单文件路线在 Windows 的坑是连串的（deploy
   hoisting / pkg 快照 / junction），而 **KCoder 在 Windows 上根本不用
   单文件 SEA**——它就是把运行时当 node_modules 目录树跑（mac 上解包
   其 asar 与 runtime 目录可证）。KStock dev 早已具备同款路径
   （`node --import tsx/esm apps/cli/src/bin.ts`；vendor/qilin 依赖已装、
   Node 24 达标），只是被「dist-exe 存在即优先」挡住。修法：
   `resolveEngineLaunch` 对 dev exe 加 `--help` 冒烟（30s），不过即记
   日志落源码直跑，不再让半成品 exe 卡死整条启动链。macOS 实测：用
   退出码 1 的假 exe 触发 → 冒烟拦截 → 源码直跑引擎完整启动（主题
   上报 dark）。Windows 侧配套仅需
   `cd vendor/qilin && ../../scripts/qilin-pnpm.sh run build` 生成
   packages/*/lib（源码直跑前置）；
9. **pnpm 脚本前 deps 自检：炸 postinstall + 剪 devDeps**（实机两连击）。
   ① 先炸 postinstall：`pnpm install --production` 下 vendor 根 postinstall
   `install-lefthook.mjs` 静态 `import 'lefthook/package.json'`
   （devDependency）→ ERR_MODULE_NOT_FOUND → install exit 1 → 连带 build
   失败；② 修掉后暴露更隐蔽的一层：该自检用**上次安装记录的 settings**
   重放安装，而 build-engine-bundle 步过 `pnpm deploy --prod`，工作区
   状态里 production=true → 自检实际执行 `--production` 安装 →
   **devDependencies 被剪掉**（tsx/typescript 消失）→ `tsx scripts/build.ts`
   报「不是内部或外部命令」。三处修：① `qilin-pnpm.sh` 导出
   `pnpm_config_verify_deps_before_run=false`（读 pnpm 源码确认：只认
   `pnpm_config_` 前缀，且 switch 无 default 分支 = 置 false 即静默跳过；
   首轮误用 `npm_config_` 前缀无效，已修正；`pnpm config get` 实测：
   包装器下 false、裸 pnpm 为 undefined）；② patcher 补丁 15 把 postinstall
   静态导入改可选（缺 lefthook 静默降级，macOS 实测隐藏 lefthook 后
   exit 0）；③ 受影响机器重跑 `qilin-pnpm.sh install --frozen-lockfile`
   恢复 devDeps。
