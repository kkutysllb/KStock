# 故障排查

## 1. `pytest` 找不到包

先确认 Python 运行时依赖已同步（gateway 依赖由 uv 统一管理）：

```bash
uv sync
```

## 2. `pnpm test` 报依赖缺失

重新安装前端依赖：

```bash
pnpm install
```

## 3. Electron 桌面端没有启动

确认使用的是桌面入口：

```bash
pnpm dev:desktop
```

Electron 主进程会自动编译 `electron/main.ts` → `dist-electron/main.cjs` 并拉起 gateway 子进程；若端口 1420（Vite）或 18001（gateway）被占用，先排查残留进程。

## 4. Playwright 提示没有浏览器

安装 chromium：

```bash
pnpm -C apps/desktop exec playwright install chromium
```

## 5. 技能包校验失败

重新同步精选技能：

```bash
python scripts/sync_upstreams.py --sync-skills
python scripts/verify_skill_pack.py
```

## 6. QiLin 包看不到或发布包缺失

重新同步 QiLin 内置快照（同步后重启 gateway 生效）：

```bash
python scripts/sync_upstreams.py --sync-qilin
uv sync
```

## 7. 用户数据目录异常

如果 sidecar 健康检查返回 `developmentFallback: true`，说明当前没有收到正式应用数据目录，正在使用仓库内 `.kstock`。开发时可以接受；发布包中出现该状态需要检查 Electron 主进程（`apps/desktop/electron/lib/gateway.ts`）是否正确传入 `KSTOCK_APP_DATA_DIR`。

如果线程历史或报告丢失，先检查：

- `QILIN_HOME` 是否指向 `<KStock 数据目录>/runtime/qilin`
- `qilin.runtime.yaml` 中 `database.sqlite_dir` 是否为绝对路径
- 当前 `activeUserId` 是否和线程目录 `runtime/qilin/users/{user_id}` 一致

## 8. `pnpm` 报「requires at least Node.js v22.13」

典型现象：终端里 `pnpm` 单独可用，但 `./build-release.sh` 执行到检查阶段报
`This version of pnpm requires at least Node.js v22.13`。

根因：机器上有多套 Node（如 homebrew 的新版 + `/usr/local/bin/node` 旧版
v22.11.0），而登录 shell（`bash -l`）会经 `path_helper` 重建 PATH，把
`/usr/local/bin` 排到 homebrew 之前——选中旧版 Node 后，新版 pnpm
（11.x 要求 Node ≥22.13）直接拒绝启动。`build-release.sh` 已内置对齐
（`prefer_homebrew_node` + 非登录 `bash -c` 执行子命令 + 前置兼容性预检）。

如果预检仍然失败，按提示任选其一：

```bash
brew upgrade node                        # 升级 homebrew Node
sudo rm /usr/local/bin/node              # 或移除旧版 node（确认无其他依赖）
npm i -g pnpm@9.15.0                     # 或降级 pnpm 到 packageManager pin 版本
```

诊断当前环境选中的是哪套工具链：

```bash
which -a node pnpm   # 列出所有候选及实际命中的顺序
bash -lc 'which node; node -v'   # 模拟发布脚本内部的登录 shell 视角
```
