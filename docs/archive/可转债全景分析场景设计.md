# 可转债全景分析场景设计

> 版本：v1.0（2026-08-02）
> 状态：模板编排机制已落地（lead_soul.md「可转债全景分析场景」节 + 前端简洁请求 + cb-analysis 周度综合引擎），待 L2 端到端验证
> 前置条件：32 个技能全量端到端验证通过（见 [技能可用性报告](技能可用性报告.md)），cb-analysis 周粒度引擎 L1 已验证

## 一、场景定义

**场景（Scenario）= 简洁用户消息 + 提示词模板编排**。与[股指期货专题分析场景](股指期货专题分析场景设计.md)、
[期权ETF专题分析场景](期权ETF专题分析场景设计.md)同一机制：用户在桌面端空态工作台点击场景卡片，前端仅填入
**简洁研究请求**（如"请做一份可转债全景分析（周度）"）；完整的编排指令（委派哪些子代理、执行哪些技能脚本、
共振/背离标注规则、输出结构）由 **Lead Agent 提示词模板**（`config/lead_soul.md` → `QILIN_HOME/SOUL.md` →
系统提示 `<soul>` 块）承载，**不进入用户消息**。

本场景：**可转债全景分析**——以全市场存续可转债为分析对象，完成「市场温度与结构 → 估值与策略 → 正股联动与
条款」多层协同分析，输出市场温度 / 规模结构 / 估值全景 / 资金情绪 / 双低策略池 / 条款事件 / 综合研判的
全景结论。支持**日度 / 周度**双粒度：

| 粒度 | 数据源 | 分析口径 | 主要引擎 |
|------|--------|----------|----------|
| 日度 | 同花顺问财 OpenAPI（实时） | 16 大看板模块 + 智能筛选 + 单只深度 | cli.py dashboard / selector / analyze |
| 周度 | Tushare Pro（T+1） | ISO 自然周聚合，全市场估值快照 | analyze_weekly_cb.py |

## 二、提示词模板机制（编排指令的载体）

### 2.1 模板链路（与股指期货/期权ETF场景同机制）

```
config/lead_soul.md（仓库模板，Git 管理）
  │  run_gateway.py::_ensure_default_soul（首次启动写入，已存在保留用户内容）
  ▼
QILIN_HOME/SOUL.md（运行时，~/.kstock/runtime/qilin/SOUL.md）
  │  QiLin 引擎 load_agent_soul → 渲染进 lead agent system prompt 的 <soul> 块
  ▼
Lead Agent（所有对话的持久行为约束，用户不可见）
```

模板新增「可转债全景分析场景」一节：粒度识别（日度/周度）、多维度子代理委派流程
（read_file 激活技能 → 固定命令模板）、全景信号表与共振/背离标注规则、场景约束。

### 2.2 模板内容（config/lead_soul.md 场景节要点）

1. **粒度识别**：用户消息含「周度」「周报」→ 周度流程；否则默认日度
2. **市场温度与结构维度**：委派 general-purpose——`read_file` 读 `cb-analysis/SKILL.md`（密钥激活）
   → 周度 `cd /mnt/skills/public/cb-analysis/scripts/analysis-engine && python3 analyze_weekly_cb.py`
   （需近 N 周对比加 `--weeks 2`）；日度 `python3 cli.py dashboard`（16 大模块，重点
   forced-redeem / downrev-count / top10 / premium-analysis / small-scale）→ 转述市场温度
   （周度：中证转债指数周涨跌/周均成交/近 N 周对比）
3. **估值与策略维度**：同构委派 cb-analysis——周度从 `analyze_weekly_cb.py` 输出转述估值全景
   （均价/平均溢价率/双低/价格分档）与双低策略池 TOP10；日度 `cli.py select --query "双低值排名前20的
   可转债"` 与 `cli.py analyze --mode single`（用户指定个券时）→ 转述估值快照表与双低/个券清单
4. **正股联动与条款维度**（可选）：同构委派 `stock-analysis`（`get_finance_data_gateway().daily` 查正股）；
   周度引擎已含条款事件（cb_call 强赎/到期公告），日度补充 `cli.py dashboard --module forced-redeem`
   与 `--module arbitrage`（转股折价套利）
5. **汇总输出**：可转债全景信号表（市场温度/估值/资金/条款事件/综合方向）+ 共振/背离标注
   （见 2.3）+ 场景综合评分（0-100）+ 一句话结论
6. **场景约束**：子代理禁止 shell 重定向/写文件/路径探查；命令报错原样转述

> 运行时 SOUL.md 与模板 diff 一致时可安全覆盖同步；若已被用户修改，需人工合并场景节。

### 2.3 共振 / 背离标注规则（场景节第 5 条）

| 规则 | 判据 | 标注 |
|------|------|------|
| 量价共振偏多 | 指数周涨 + 平均溢价率回落 + 周均成交放大 | 共振偏多 |
| 防御性上涨 | 指数上涨但平均溢价率大幅抬升（>2pct） | 背离（股性弱化） |
| 逆向布局窗口 | 指数下跌但平均双低走低、低价债占比扩大 | 背离（安全边际增厚） |
| 缩量上涨 | 指数上涨但周均成交清淡（<80 亿） | 背离（持续性存疑） |
| 条款风险 | 强赎/到期公告密集 + 高溢价标的 | 风险警示 |
| 双低窗口 | 双低池扩容 + 指数企稳 | 双低策略窗口开启 |

## 三、分析技能层周粒度扩展（本次新增）

cb-analysis 技能新增**可转债周度全景综合引擎** `scripts/analysis-engine/analyze_weekly_cb.py`，
与 futures-analysis / option-futures-linkage / etf-analysis 的周粒度能力对齐。

### 3.1 能力声明（SKILL.md v1.1.0）

- `capabilities` 新增 `cb-weekly`：全市场存续转债按 ISO 自然周聚合——市场温度（中证转债指数
  000832.CSI 周涨跌/周均成交/近N周对比）/市场规模与结构（存续只数·总余额·新上市·退市·条款事件）/
  估值全景（均价·溢价率·双低·价格分档·双低策略池TOP10）/资金与情绪（周成交总额·周均日成交）/
  综合研判（0-100分评分·积极/风险信号/条款提示）
- `requires` / `required-secrets` 新增 `TUSHARE_TOKEN`（周度引擎数据源），与 `IWENCAI_API_KEY`（日度）并存
- 正文新增「引擎4: 可转债周度全景综合引擎」执行方式与周度口径说明

### 3.2 周度口径

- **周窗口**：ISO 自然周聚合（周标签形如 `2026-W31`），默认最近一周，`--weeks N` 回溯（近 N 周指数对比表）
- **转股价值**：100 / 转股价 × 正股收盘（周首/周末两日快照）
- **转股溢价率**：(转债收盘 − 转股价值) / 转股价值
- **双低值**：转债价格 + 转股溢价率（百分点），双低策略池取周末快照 TOP10
- **金额单位**：cb_daily.amount 万元（÷1e4 → 亿元）；index_daily.amount 千元（÷1e5 → 亿元）；
  cb_basic.remain_size 元（÷1e8 → 亿元）
- **评分模型**：指数周涨跌（±15）+ 平均溢价率变化（∓10）+ 双低水位（±8）+ 周均日成交（±8）
  → 0-100 分，≥58 偏多 / ≤42 偏空 / 其余中性震荡

### 3.3 输出结构（脚本 stdout，Markdown 模板）

| 章节 | 内容 |
|------|------|
| 一、市场温度 | 中证转债指数 000832.CSI 周初/周末收盘、周涨跌幅、周均/周总成交、周内每日明细、近 N 周对比 |
| 二、市场规模与结构 | 存续只数/总余额/周内新上市/退市、条款事件表（强赎/到期公告） |
| 三、估值全景 | 周初→周末均价/平均溢价率/平均双低/中位价格/平均余额、价格分档分布、双低策略池 TOP10 |
| 四、资金与情绪 | 转债周成交总额/周均日成交/单日最大成交/周内交易日 |
| 五、综合研判 | 综合评分（0-100）+ 方向 + 信号明细 + 积极/风险信号 + 条款事件提示 |
| 六、小s的总结 | 关键结论四要素 + 特别注意（按评分区间给出策略倾向） |

### 3.4 数据源与容错

- Tushare Pro：`cb_basic`（基础信息/转股价/剩余规模）/ `cb_daily`（转债日线，全市场按日拉取）/
  `cb_call`（强赎/到期条款事件）/ `index_daily`（000832.CSI 中证转债指数）/ `daily`（正股行情，仅周首/周末）
- 单接口失败不影响其他（error 字段标注，缺失如实呈现）
- 最新交易日优先由中证转债指数行情推断（trade_cal 权限缺失时兜底）
- 估值计算在正股/转债数据缺失时跳过，双低池为空时如实说明

## 四、前端引导机制（落地位置：apps/desktop/src/pages/Home.tsx）

### 4.1 数据结构（复用既有 ResearchScene）

```tsx
interface ResearchScene {
  id: string;          // 场景唯一标识，如 "cb-weekly"
  title: string;       // 卡片标题，如 "可转债全景分析 · 周度"
  description: string; // 一句话说明（卡片副标题）
  prompt: string;      // 简洁研究请求（点击后填入输入框，单行）
}

const researchScenes: ResearchScene[] = [
  { id: "index-futures-daily",  title: "股指期货专题分析 · 日度", ... },
  { id: "index-futures-weekly", title: "股指期货专题分析 · 周度", ... },
  { id: "option-etf-daily",  title: "期权ETF专题分析 · 日度", ... },
  { id: "option-etf-weekly", title: "期权ETF专题分析 · 周度", ... },
  { id: "etf-normal-daily",  title: "普通ETF专题分析 · 日度", ... },
  { id: "etf-normal-weekly", title: "普通ETF专题分析 · 周度", ... },
  { id: "cb-daily",  title: "可转债全景分析 · 日度",
    prompt: "请做一份可转债全景分析（日度）" },
  { id: "cb-weekly", title: "可转债全景分析 · 周度",
    prompt: "请做一份可转债全景分析（周度）" },
];
```

### 4.2 交互流程（与股指期货场景一致）

```
空态工作台（workspace-empty）
  │  ┌─ 研究场景区块（research-scenes）─────┐
  │  │ 场景卡片：标题 + 描述 + 图标          │  ← 本次新增 2 张（日度/周度）
  │  └──────────────────────────────────────┘
  ▼
点击场景卡片 → onDraftChange(scene.prompt) → 简洁请求填入输入框（可编辑）
  ▼
用户发送 → Lead Agent 从 <soul> 模板识别「可转债全景分析」场景 → 按模板编排执行
```

- 场景卡片点击只填输入框、不直接发送，用户可查看/调整粒度后再发送
- **用户消息保持自然语言简洁，不承载任何编排指令**

## 五、Agent 编排流程（收到请求后，由模板驱动）

```
请求（周度）："请做一份可转债全景分析（周度）"
  │  Lead Agent 从 <soul> 模板识别场景 → 委派
  ▼
Lead Agent（编排）
  ├─ Subagent A：cb-analysis ──────── 周度 analyze_weekly_cb.py（市场温度/规模结构/估值/资金/双低池/综合研判）
  ├─ Subagent B（估值策略，可复用 A 输出）── 估值全景与双低策略池 TOP10（日度：select + analyzer）
  └─ Subagent C（可选）：stock-analysis ── 正股行情联动（get_finance_data_gateway().daily）
      日度补充 forced-redeem / arbitrage 模块
  │
  ▼
Lead Agent 汇总：全景信号表（温度/估值/资金/条款/综合方向）+ 共振/背离标注 + 综合评分
  ▼
交付：AI 总结（含市场温度表、估值全景表、双低策略池表、条款事件表）
```

> 子代理委派由模型自主决策（实测 lead 也可能自行执行部分技能，结果等价）；
> 周度主分析为单脚本覆盖（analyze_weekly_cb.py 一次产出全维度），子代理数量上限 3 内。

## 六、输出结构（AI 总结应包含）

| 区块 | 内容 | 来源 |
|------|------|------|
| 全景信号表 | 市场温度/估值/资金/条款事件/综合方向 | Lead 汇总 |
| 市场温度 | 中证转债指数周涨跌/周均成交/近 N 周对比（日度：16 大模块核心） | Subagent A |
| 规模与结构 | 存续只数/总余额/新上市/退市 | Subagent A |

## 七、验证方式

1. **技能层验证（L1 宿主机）**：`python3 analyze_weekly_cb.py` 输出全市场真实数据（周标签为当前
   ISO 周，如 2026-W31），存续只数/总余额/双低池与 Tushare 原始数据一致；`--weeks 2` 输出近两周
   指数对比；`--json` 输出原始结果；日度 `cli.py dashboard --module forced-redeem` 等模块正常
2. **模板静态验证**：`config/lead_soul.md`「可转债全景分析场景」节与运行时 `QILIN_HOME/SOUL.md` diff 一致
3. **前端静态验证**：`tsc --noEmit`（类型） + `vitest run`（单元测试） + `vite build`
4. **交互验证**：桌面端进入空态工作台 → 点击"可转债全景分析 · 周度"卡片 → 输入框出现简洁请求（非编排指令）→ 发送
5. **端到端验证（L2 沙箱）**：以简洁请求作为 SSE 任务输入，检查 Lead Agent 从 SOUL 模板识别场景、
   子代理 completed、温度/估值/双低/条款表齐全、run 自然结束
6. **周度复验**：同法跑日度请求，验证 dashboard 16 大模块路径
