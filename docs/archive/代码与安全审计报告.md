## 二、两条关键攻击链（多报告交叉印证）

1. **恶意报告 → 盲打已认证接口**：沙箱 iframe（sandbox="allow-scripts"）中的报告 HTML 可执行脚本 → fetch app://localhost/gateway/api/...（multipart 简单请求无预检）→ protocol.handle 不校验 Origin 并注入 CSRF token + 会话 cookie（Top-1）→ 已认证写接口被盲打。修 Top-1 一举封死；纵深上再修 sanitizePreviewHtml 假消毒（仅删 Vite 脚本，P2）与 CSP（Top-8）。
2. **本机多用户 → 宿主 bash**：gateway 绑 loopback（本机所有用户可达）→ 注册默认开放（Top-3）+ 无 Origin 头请求免 CSRF + 授权默认全权限 → 自注册用户经 agent 的 host bash 以 KStock 属主身份执行命令（读 secrets.env）。修 Top-3 断链。

## 六、已确认防护良好的点（证明已查，摘要）

- **Electron 基线**：contextIsolation/sandbox 开、nodeIntegration 关；打包态禁回连 dev server；单实例锁；openExternal 仅 http(s)；openPath 枚举白名单；saveArtifact 写路径由用户对话框决定；app:// 静态服务路径穿越防护有效（含 %2e%2e 双编码）；代理目标硬编码 localhost:18001。
- **渲染内容**：react-markdown 无 rehype-raw（raw HTML 转义）、javascript: 被默认 urlTransform 拦截；两个预览 iframe 均无 allow-same-origin（同源逃逸被阻断）。
- **gateway**：全局 fail-closed 认证；CSRF double-submit 覆盖全部 kstock 写路由无豁免；GET 模型/数据源只回 $ENV 引用与布尔、无明文 key；secrets.env 0600 原子写；.jwt_secret 0600；启动日志只打印密钥数量；报告库 _SAFE_COMPONENT 白名单 + resolve/parents 复核；上传链 O_NOFOLLOW/nlink/relative_to；make_safe_user_id 防跨用户；全库无 eval/exec/pickle/yaml.load；绑定 localhost 覆盖 vendor 默认 0.0.0.0。
- **打包/CI**：打包面干净（无 .env/~/.kstock/.git，构建前 rm -rf 旧产物）；CI 用 pull_request（fork PR 无 secrets）；latest.yml↔资产名交叉校验已有自动防线；allowDowngrade 关闭。
- **vendor 集成健康**：scripts/tests 引用的全部 vendor 符号均存在（无漂移）；config/qilin.config.yaml 无死键；pyproject 依赖声明与实际 import 一致；kstock-gateway.spec hiddenimports 中动态 import 项均必要。
