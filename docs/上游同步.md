# 上游同步说明

## 本地源仓库

- QiLin：`/Users/libing/kk_Projects/QiLin`
- KSkills：`/Users/libing/kk_Projects/KSkills`

## 同步命令

```bash
python3 scripts/sync_upstreams.py --refresh-lock
python3 scripts/sync_upstreams.py --sync-qilin
python3 scripts/sync_upstreams.py --sync-skills
```

## 校验命令

```bash
python3 scripts/verify_skill_pack.py
```

## 规则

- 只同步批准清单里的技能
- QiLin 同步到 `vendor/qilin`，作为产品发布输入
- 不直接修改上游仓库
- 所有产品定制留在 KStock

## 同步后的自动重放

- `sync_upstreams.py --sync-skills` 会在复制完成后调用 `patch_vendor_skills.py`
  幂等重放全部本地补丁（脚本修复 + 旧工具引用改写）。
- KStock 自有技能 `kstock/skills/html-report` 也会被重放进
  `vendor/skills/public/html-report`（上游覆盖不丢失，源头在仓库内）。
- 引擎快照（`--sync-qilin`）后需重装引擎依赖并重建产物（快照排除规则会
  连带清掉 `lib/`、`dist/`、`dist-exe/`、`node_modules/`，全部要重建）：

  ```bash
  cd vendor/qilin && ../../scripts/qilin-pnpm.sh install --frozen-lockfile
  ../../scripts/qilin-pnpm.sh run build                    # 重建 lib/
  ../../scripts/qilin-pnpm.sh run verify-runtime-closure   # 预设↔闭包清单闭环门禁（应报 N≥11 presets）
  cd ../.. && bash scripts/build-runtime-bundle.sh         # 重建 staging 运行时闭包
  ```

  - `verify-runtime-closure` 是打包必经门禁：校验每个 preset 引用的插件都在
    `python/sdk-runtime` 依赖清单里（KStock 预设经补丁 22 一并纳入）。
  - `build-runtime-bundle.sh` 未设 `APPLE_SIGNING_IDENTITY` 时跳过 Developer ID
    预签（本地开发闭包）；发布/公证场景必须携带。
  - 旧 SEA 单文件路径（`build-engine-bundle.sh --force-exe-build` →
    `dist-exe/kstock-engine`）已退役，仅在需要新旧形态回归对比时手动跑。
  - 上游 lock 与快照来自上游**工作树**（非 git 提交），同步前务必确认
    上游工作区干净（`git -C /Users/libing/kk_Projects/QiLin status`）。

## 版本口径

- `upstream.lock.json` 的 version 与上游 tag 一致（tag 与 package.json 同号，
  如 v3.0.5 ↔ 3.0.5）；早于 3.0.5 的历史快照曾出现 tag 领先一个号的情况。

## 补丁失配即失败（3.0.5 起）

- 引擎本地补丁（`patch_vendor_engine.py` + `patch_vendor_skills.py` 的引擎段）
  锚点失配时**响亮失败**：`--sync-qilin` 的补丁重放失败会让同步以非零退出，
  `patch_vendor_skills.py` 单独运行也会打印失配清单并以 1 退出。
- 处置：对照上游新形态更新补丁脚本里的锚点常量后重放（见实施手册失败
  手册 S3）；绝不为了过门禁删除补丁。
