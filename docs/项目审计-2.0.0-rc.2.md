## 一、安全漏洞

### S-1〔HIGH · 已修复〕electron-updater 依赖链 js-yaml 高危漏洞

- **发现**：`pnpm audit --prod`（apps/desktop）报 1 high——`electron-updater@6.8.9 → js-yaml@4.3.1`
  （[GHSA-2883-xcg3-v3hh](https://github.com/advisories/GHSA-2883-xcg3-v3hh)，修复版 ≥4.3.2）。
- **影响面**：js-yaml 是 updater 解析 `latest*.yml` 更新源的运行时依赖——**自动更新链路的核心解析器**。
- **修复**：根 `package.json` 增 pnpm override `"js-yaml@<4.3.2": ">=4.3.2"` → 重装解析为
  `js-yaml@5.4.2`；`pnpm install --frozen-lockfile` 通过（CI 安全）；审计清零。
- **验证**：`pnpm why js-yaml` → `electron-updater 6.8.9 └── js-yaml 5.4.2`；`pnpm audit --prod` →
  `No known vulnerabilities found`。

### S-2〔核查 · 通过〕无硬编码秘密

全仓 tracked 文件扫描（AKIA/私钥头/sk-长串/ghp_/xox 族）：命中 2 处均为上游
`vendor/qilin` 遥测**测试夹具中的假密钥**（`sk-e2efixture…`，用于验证脱敏逻辑），非真实凭据。
`.env` / `.qilin-internal-token` 在上游同步排除清单内（`sync_upstreams.py` 顶层排除），不入仓。

### S-3〔核查 · 通过〕静态资源路由无路径穿越

- `kstock/web` `/kstock/*` 路由：仅允许一级文件名，显式拒绝 `/`、`\`、`..`（`kstock/web/src/index.ts:90`）；
- 认证页跳转：`kstock-auth.js` 对 `requested` 做 URL 噪声过滤（含反斜杠即回默认入口）。

### S-4〔核查 · 通过〕无代码注入面；更新器安全配置正确

- 产品层源码无 `eval` / `new Function` / `exec(·)` 动态执行（扫描命中均为正则 `.exec()` 误报与构建 sourcemap）；
- 自动更新（`updater.ts`）：HTTPS GitHub feed、`autoDownload` + 退出兜底安装、无降级路径、
  安装前先同步终止引擎进程树（避免文件占用/端口冲突）、`quitAndInstall` 失败可见可重试；
  发布说明兜底拉取带 6s 超时与静默降级，不阻塞更新主流程。

### S-5〔核查 · 通过〕发布链安全门禁（R6.1 已固化，本轮复核）

macOS 签名+公证 fail-closed（缺凭据构建门前拦截）、Windows 产物无 publisherName 污染（V7 语义）、
tag 不可变 SOP、`verify_release_assets` 资产交叉比对。

## 二、冗余代码

### R-1〔低 · 记录不改〕electron-builder 传递依赖版本偏斜

`electron-builder@26.15.3` 的传递依赖 `electron-builder-squirrel-windows@25.1.8` 拉入
`app-builder-lib@25.1.8`，与主链 `dmg-builder@26.15.3` peer 不齐（安装期 unmet peer 警告）。
Squirrel.Windows 目标**未使用**（发布目标：mac zip/dmg + NSIS + deb/rpm），不影响产物与运行时；
待 electron-builder 后续版本收敛传递依赖后自然消除。

### R-2〔低 · 已修正注释〕引擎双产物链（设计冗余，保留）

打包态走运行时闭包 tar（`build-runtime-bundle.sh`），dev 态走 SEA 单文件（`build-engine-bundle.sh`）
+ 源码直跑兜底——三级解析是**有意的 dev 兼容设计**。但 `engine.ts` 注释「新流程已不再产出（dist-exe）」
与实际产出矛盾 → 已修正为准确表述（dev 首选 SEA 单文件）。
