# 股指期货专题分析场景设计

> 版本：v3.0（2026-08-02）
> 状态：模板编排机制已落地（lead_soul.md 场景节 + 前端简洁请求），待 L2 端到端验证
> 前置条件：32 个技能全量端到端验证通过（见 [技能可用性报告](技能可用性报告.md)）

## 一、场景定义

**场景（Scenario）= 简洁用户消息 + 提示词模板编排**。用户在桌面端空态工作台点击场景卡片，
前端仅填入**简洁研究请求**（如"请做一份股指期货专题分析（日度）"）；完整的编排指令（委派
哪些子代理、执行哪些技能脚本、共振/背离标注规则、输出结构）由 **Lead Agent 提示词模板**
（`config/lead_soul.md` → `QILIN_HOME/SOUL.md` → 系统提示 `<soul>` 块）承载，**不进入用户消息**。

本场景：**股指期货专题分析**——以四大股指期货（IF/IH/IC/IM）为核心标的，
完成「期指维度 → 期权联动维度 → 市场环境维度」三层协同分析，
输出四品种方向矩阵与共振/背离标注。支持**日度 / 周度**双粒度。

## 二、提示词模板机制（编排指令的载体）

### 2.1 模板链路（既有机制，本次扩展）

```
config/lead_soul.md（仓库模板，Git 管理）
  │  run_gateway.py::_ensure_default_soul（首次启动写入，已存在保留用户内容）
  ▼
QILIN_HOME/SOUL.md（运行时，~Library/Application Support/KStock/runtime/qilin/SOUL.md）
  │  QiLin 引擎 load_agent_soul → 渲染进 lead agent system prompt 的 <soul> 块
  ▼
Lead Agent（所有对话的持久行为约束，用户不可见）
```

模板新增「股指期货专题分析场景」一节（v3）：粒度识别（日度/周度）、三维度子代理委派流程
（read_file 激活技能 → 固定命令模板）、四品种方向矩阵与共振/背离标注规则、场景约束。

### 2.2 模板内容（config/lead_soul.md 场景节要点）

1. **粒度识别**：用户消息含「周度」→ 周度流程；否则默认日度
2. **期指维度**：委派 general-purpose——`read_file` 读 `futures-analysis/SKILL.md` 前 80 行（密钥激活）
   → `cd .../futures-analysis/scripts/analysis-engine && python3 analyze_futures.py`（周度 `analyze_weekly_futures.py`）
   → 转述四品种行情/基差/持仓表与「中信 vs 其他机构」对比表
3. **期权联动维度**：同构委派 `option-futures-linkage`，执行 `analyze_option_futures.py`（周度
   `analyze_weekly_option_futures.py`）→ 转述 PCR/ATM IV/IV 斜率/RR 与 5 维联动信号表
4. **市场环境维度**：同构委派 `market-linkage-engine`，完成 8 维联动分析并转述联动评分
5. **汇总输出**：IF/IH/IC/IM 方向矩阵 + 共振/背离标注（贴水+PCR 偏空+RR 认沽贵=三向共振偏空；
   升水但 PCR 偏空=背离；北向流出+两融降+IV 抬升=环境印证偏空；IF/IH 多 vs IC/IM 空=风格切换）
   + 综合评分 + 一句话结论
6. **场景约束**：子代理禁止 shell 重定向/写文件/路径探查；命令报错原样转述

> 运行时 SOUL.md 与模板 diff 一致时可安全覆盖同步；若已被用户修改，需人工合并场景节。
> 后续模板更新建议增加版本标记，`_ensure_default_soul` 按版本增量合并。

## 三、前端引导机制（落地位置：apps/desktop/src/pages/Home.tsx）

### 3.1 数据结构

```tsx
interface ResearchScene {
  id: string;          // 场景唯一标识，如 "index-futures-daily"
  title: string;       // 卡片标题，如 "股指期货专题分析 · 日度"
  description: string; // 一句话说明（卡片副标题）
  prompt: string;      // 简洁研究请求（点击后填入输入框，单行）
}

const researchScenes: ResearchScene[] = [
  { id: "index-futures-daily",  title: "股指期货专题分析 · 日度", ...,
    prompt: "请做一份股指期货专题分析（日度）" },
  { id: "index-futures-weekly", title: "股指期货专题分析 · 周度", ...,
    prompt: "请做一份股指期货专题分析（周度）" },
];
```

### 3.2 交互流程

```
空态工作台（workspace-empty）
  │  ┌─ 研究场景区块（research-scenes）─────┐
  │  │ 场景卡片：标题 + 描述 + 图标          │  ← 本次新增
  │  └──────────────────────────────────────┘
  │  ┌─ 快捷引导区（quick-prompt-grid）─────┐
  │  │ 单行快捷词 × 4                       │  ← 既有
  │  └──────────────────────────────────────┘
  ▼
点击场景卡片 → onDraftChange(scene.prompt) → 简洁请求填入输入框（可编辑）
  ▼
用户发送 → Lead Agent 从 <soul> 模板识别「股指期货专题分析」场景 → 按模板编排执行
```

- 场景卡片点击只填输入框、不直接发送，用户可查看/调整粒度后再发送
- **用户消息保持自然语言简洁，不承载任何编排指令**（v2 缺陷：编排指令混入用户消息）

## 四、Agent 编排流程（收到请求后，由模板驱动）

```
请求（日度）："请做一份股指期货专题分析（日度）"
  │  Lead Agent 从 <soul> 模板识别场景 → 并行委派 3 个子代理
  ▼
Lead Agent（编排）
  ├─ Subagent A：futures-analysis ──── 期指四维（行情/基差/持仓/中信vs其他机构对比）
  ├─ Subagent B：option-futures-linkage ── 期权五维 × 5 维联动信号
  └─ Subagent C：market-linkage-engine ─── 8 维市场联动
  │
  ▼
Lead Agent 汇总：四品种方向矩阵 + 共振/背离标注 + 综合评分
  ▼
交付：AI 总结（含方向矩阵表、中信对比表、联动信号表）
```

> 子代理委派由模型自主决策（实测 lead 也可能自行执行部分技能，结果等价）；
> `max_total_per_run=6` 覆盖 3 个子代理上限。

## 五、输出结构（AI 总结应包含）

| 区块 | 内容 | 来源 |
|------|------|------|
| 方向矩阵 | 四品种 ×（期指/期权/联动/综合） | Lead 汇总 |
| 期指维度 | 行情/基差/持仓 + 中信 vs 其他机构对比表 | Subagent A |
| 期权维度 | PCR/ATM IV/IV斜率/RR + 联动信号表 | Subagent B |
| 市场环境 | 8 维联动评分 | Subagent C |
| 结论 | 共振/背离清单 + 综合评分 + 一句话结论 | Lead 汇总 |

## 六、验证方式

1. **模板静态验证**：`config/lead_soul.md` 场景节与运行时 `QILIN_HOME/SOUL.md` diff 一致
2. **前端静态验证**：`tsc --noEmit`（类型） + `vitest run`（单元测试） + `vite build`
3. **交互验证**：桌面端进入空态工作台 → 点击"股指期货专题分析 · 日度"卡片 → 输入框出现
   简洁请求（非编排指令） → 发送
4. **端到端验证（L2 沙箱）**：以简洁请求作为 SSE 任务输入，检查 Lead Agent 从 SOUL 模板识别
   场景、3 个子代理 completed、方向矩阵/三表齐全、run 自然结束
5. **周度复验**：同法跑周度请求
